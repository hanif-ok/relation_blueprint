# Phase 2 — UI Design Contract

> Visual and interaction contract for Custom Fields & the Full Entity Model. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> This phase **inherits Phase 1's visual language wholesale** (`01-UI-SPEC.md`, tokens at `src/app/tokens.ts` / `src/app/tokens.css`). It adds NO new colors, fonts, or spacing values — it reuses the established system and specifies the new surfaces (view switcher, browse lists, field manager, custom-field rendering, entity forms, lightbox, gallery reorder, privacy notice) in terms of it.

---

## Design Direction (carried forward, extended)

Phase 1 established **"The lit field map"**: a dark Konva canvas as the hero, warm-paper DOM chrome, and a single reserved amber accent for *placement and selection*. Phase 2 turns the single-surface map shell into a **multi-surface dossier** — the curator can now browse People, Locations, Groups, and Relationship-links as paper lists, not only by clicking markers. The identity holds:

- **The map remains the hero, but it is now one view among several.** A left nav swaps the main surface (D-13). The map view is unchanged from Phase 1; the four new browse surfaces are paper lists.
- **Amber stays reserved.** New surfaces add many buttons (create entity, add field, reorder, lightbox controls) — none of them may take amber except the **create-a-new-entity** action (the Phase-1 "+ Person" rule generalized to all four types) and marker placement/selection on the map. (D-13 nav, A8 carried forward.)
- **Paper chrome absorbs the new density.** Field manager, browse rows, lightbox chrome, and entity forms all use the existing paper / paper-shade / hairline system. The only dark surface remains the canvas and the lightbox backdrop (a deliberate dark scrim so photos read like the map content does).
- **Entity-type identity via quiet ink-tints + type glyphs, never new accents.** Per the Phase 1 forward note: Locations, Groups, and Relationship-links each get a quiet Lucide type glyph for their default (no-photo) thumbnail and list badge — amber is never spent on type coding. (D-15 secondary line, Claude's-Discretion per-type icons.)

This phase introduces no competing accent. Every "do it" affordance that is not *creating a new entity* is neutral ink, exactly as Edit/secondary were in Phase 1.

## Spacing Scale

Inherited unchanged from Phase 1 / `tokens.css`. 8-point scale (all multiples of 4):

| Token | Value | Phase-2 usage |
|-------|-------|---------------|
| xs | 4px | Glyph-to-label gap in nav/rows, chip padding, field-row inner gaps |
| sm | 8px | Browse-row internal stacking (name → secondary line), field-manager row gaps, gallery tile gaps |
| md | 16px | Browse-row padding, field-manager body padding, entity-form field gaps, sidebar custom-field row spacing |
| lg | 24px | Nav section padding, dialog section padding, lightbox on-screen-control inset |
| xl | 32px | Nav top/bottom rhythm, gallery grid gap at large size |
| 2xl | 48px | Browse empty-state vertical rhythm |
| 3xl | 64px | Browse empty-state top offset |

**Exceptions (carried forward + new):** icon-only controls keep a **≥44px hit area** (nav items, show-on-map button, lightbox prev/next/close, gallery drag handle, lightbox thumbnail). Top bar stays **56px**. **Browse row height: fixed 64px** (thumb 48px + 8px vertical padding) so the virtualized list can use a constant row height for windowing — this is a 4-multiple and a deliberate scale value, not an exception. **Left nav width: 240px expanded / 56px collapsed (icon-only)** — both 4-multiples. **Lightbox thumbnail strip height (optional): 64px.**

## Color

Inherited unchanged from `tokens.css`. **No new colors.** Phase 2 spends the existing palette on new surfaces:

| Role | Value | Phase-2 usage |
|------|-------|---------------|
| Dominant (60%) | `#F4F1EA` (warm paper) | Main browse surface, entity forms, field manager, profile sidebar, privacy dialog |
| Canvas surface | `#1B2230` (deep slate) | Map view (unchanged) **and** the photo lightbox backdrop scrim (at ~92% opacity) — photos are content, so they sit on the same dark surface as the map |
| Secondary (30%) | `#E7E2D6` (paper-shade) | Left nav rail, browse-row hover fill, gallery tiles, field-manager field rows, default no-photo thumbnail fill (initials/glyph), field-type badges |
| Accent (10%) | `#C8742B` (amber) | **Reserved list below — unchanged discipline** |
| Destructive | `#B23A2E` (brick) | "Delete {entity}" cascade action + its confirmation only (NOT "Remove from map") |
| Ink (text) | `#26211A` primary / `#6B6358` muted | Body/labels; muted = secondary line, counts, field IDs, empty-field placeholders |

**Accent (amber `#C8742B`) reserved exclusively for (Phase 1 list, generalized):**
1. The **create-a-new-entity** action — the `+ New` button and its menu's primary affordance, and each browse view's empty-state "Create the first {type}" CTA. (The one creative act, now for four types.)
2. The selected marker's ring + pin-stem on the canvas (unchanged).
3. The marker placement affordance (drag-to-place / drop target) (unchanged).
4. The `Synced` confirmation dot and the **focus ring** on every interactive control (now including nav items, browse rows, field-manager controls, lightbox controls, gallery drag handles).

Amber is **never** used for: the active left-nav item (use paper-shade fill + an ink left-edge bar, not amber), Edit, "Show on map", "Add field", "Remove from map", lightbox prev/next, reorder handles, the privacy-notice dismiss, field-type badges, or any selected/active list state. **Active nav item = paper background pulled forward + 3px ink-muted left-edge marker + Label-600 ink (not muted).**

**Entity-type identity (quiet ink-tints, NOT accents):** each type's default no-photo thumbnail is a paper-shade circle/rounded-square with the type's Lucide glyph in **ink-muted** (`#6B6358`); People keep the existing **initials** fallback. No saturated per-type colors — amber stays the only attention hue (Phase 1 forward note honored).

**Lightbox color:** backdrop `#1B2230` at ~92% opacity (dark scrim over whatever surface was beneath); on-screen controls are paper-colored glyph buttons with the standard amber focus ring; caption text (filename/index "3 / 8") is paper `#F4F1EA` in mono on the scrim.

Contrast: all reused pairs already meet WCAG AA (Phase 1 verified). New pair to verify in build: paper glyph buttons / paper caption on the dark scrim — paper `#F4F1EA` on slate `#1B2230` ≈ 12:1, comfortably AA/AAA.

## Per-Surface Component Specs & States

### S10 — Left-nav view switcher
- Paper-shade rail, 240px wide (expanded) / 56px (collapsed icon-only on narrow viewports, ≤900px). Right edge `elevation-1`. Sections: **Views** (Map, People, Locations, Groups, Relationship-links) → hairline divider → **Tools** (Fields, About/Privacy).
- Each item: 44px min height, Lucide glyph (ink-muted) + Label-600 text; gap sm; padding md horizontal.
- Active item: paper background pulled forward, 3px ink-muted left-edge bar, glyph + text go from ink-muted to **ink**. Never amber.
- Hover: paper-shade darkens to the standard hover fill; focus: amber ring.
- Keyboard: nav is a single tab stop group with **arrow-key roving focus** (vertical), Enter/Space activates a view, Tab moves out to the main surface. `aria-current="page"` on the active item.
- Each entity view item shows a trailing **mono count pill** of that type's records (e.g. People · 1,284) once loaded; "—" while loading.

### S11 — Browse list (×4 entity types)
- Renders on the main surface when a non-Map view is active. **Virtualized** (constant 64px row height) so it degrades to thousands of rows; media lazy-loaded per visible row (`getMedia()` object-URLs, revoked on scroll-out). (Claude's-Discretion: virtualization is a planner implementation detail; the 64px constant row height is the contract that makes it cheap.)
- View header (sticky): Heading-20 title with mono count ("Locations · 312") + a **sort toggle** ("Name A–Z" ⇄ "Recently updated") as a neutral segmented control (paper-shade, ink; active segment = paper pulled forward + ink, NOT amber). Default = Name A–Z (D-17).
- States:
  - **Loading:** 6–8 row-shaped shimmer placeholders at 64px each; never a blocking spinner.
  - **Empty:** centered on paper — type glyph (ink-muted, 32px), Display-28 heading, Body sub-line, and one **amber** "Create the first {type}" CTA (the only amber on this surface). Copy in the Copywriting Contract.
  - **Error (shard load fail):** inline brick line above the list — **"Couldn't load your {type}. They're safe in storage — try reloading."**
  - **Offline:** fully functional from Dexie; no network gating (carried-forward principle).

### S12 — Browse row
- Fixed 64px height, padding sm vertical / md horizontal, hairline bottom separator, hover = paper-shade fill + elevation-1 + radius-md.
- Left: 48px thumbnail — People = round avatar/initials (reuse `initialsOf()` from `ProfileSidebar`); Locations/Groups/Relationship-links = radius-md paper-shade square with type glyph, OR the entity's first gallery photo if present (D-21: first photo acts as thumbnail).
- Center (gap xs, stacked): **name** (Body-16 ink) + **secondary line** (Label-13 ink-muted) showing tags (chips, truncated) or the entity's first non-empty key custom field; falls back to mono "updated 2d ago" when no tags/key field. (D-15.)
- Right: **"Show on map ↗"** action (`ExternalLink` glyph, neutral icon button, 44px hit area). Disabled-with-reason for non-spatial types (Groups, Relationship-links): tooltip **"Groups aren't placed on a map."** A row **overflow `⋯`** (Radix DropdownMenu) offers Edit and the type's delete action (S21).
- **Whole row is clickable → opens the profile sidebar** (D-16). The row is a `button`/`role="button"`; "Show on map" and overflow are nested controls with `stopPropagation`. Keyboard: row focusable, Enter opens profile; show-on-map and overflow are separately tabbable within the row.

### S13 — Per-type field manager
- Radix Dialog, paper, `elevation-2`, `radius-md`, width 560px (wide) / full-screen (narrow). Title: **"{Type} fields"** (Heading-20). Opened from nav "⚙ Fields" — it edits the **currently-active entity type's** schema (D-02, D-03: per-type, not shared).
- Body: a header note (Body, ink-muted) — **"These fields apply to every {type}. Built-in fields can't be removed."** — then the **built-in spine** rendered as locked rows (lock glyph, no edit/remove), then the **ordered custom-field list** (each row = drag handle + field name + field-type badge + Edit + Remove), then a footer **"+ Add field"** (neutral button — adding a *field definition* is not creating an *entity*, so NOT amber).
- Reorder: drag rows by the `GripVertical` handle; order persists to the per-type schema (D-02). Keyboard reorder: handle is focusable, ↑/↓ moves the field, announced via `aria-live`.
- Footer actions: **"Done"** (neutral primary, closes) — schema edits apply live (each add/edit/remove/reorder is its own mutation through the repository pattern); there is no batch "save schema" step.
- States: **empty custom fields:** muted line under the spine — **"No custom fields yet. Add one to capture more about each {type}."** **Reorder in flight:** the dragged row lifts (elevation-2), others shift with reduced-motion-respecting transition.

### S14 — Field editor (add / edit a definition, within S13)
- Inline expanding row (or nested sub-dialog on narrow). Fields: **Field name** (text, required), **Type** (select: Text, Number, Date, Phone, Tags/Select, Link to entity, Photo — the 7 DATA-03 types), **Required** (toggle, the only validation knob per D-06). For **Tags/Select**, an option-list editor (chip add/remove). For **Link to entity**, a target-type select (which entity type this points at — D-10 one-way pointer).
- Type-change warning: if editing an existing field's type, inline caution-ochre note — **"Changing the type keeps values that still fit; others are set aside, not deleted."** (Surfaces D-05 soft-conversion in the user's voice.)
- Remove a field: confirm dialog (NOT brick — this is reversible soft-delete per D-05): Title **"Remove this field?"** Body **"'{Field}' disappears from forms and profiles, but its saved values are kept. Re-add the field to bring them back."** Buttons **"Remove field"** (neutral) / **"Cancel"**. (Distinct from entity deletion, which IS brick.)
- Validation: empty field name → inline brick **"Give the field a name."** Save disabled until non-empty.

### S15 — Custom-field rendering (read, in ProfileSidebar)
- Custom fields render **after** all built-ins, in the schema's defined order (D-02 order; Claude's-Discretion: flat list after built-ins, reusing the existing `ProfileSidebar` row pattern — Label-13 ink-muted label above Body-16 ink value). Empty values: the **row is omitted** (consistent with Phase 1 "empty field rows are omitted"), EXCEPT in edit mode where all defined fields show.
- Per-type read rendering:
  - **Text / Number / Phone:** Body-16 plain text. **Phone** is a `tel:` link in ink (not amber). All values rendered as **React children — never `dangerouslySetInnerHTML`** (T-03-01 / code-context: XSS would exfiltrate the Drive token).
  - **Date:** formatted human date (Body-16); raw ISO in a mono `title`.
  - **Tags/Select:** paper-shade `radius-pill` chips (reuse Phase-1 tag chip visual).
  - **Link to entity:** the linked entity's name as a neutral-ink inline link with a small type glyph; clicking opens that entity's profile (one-way, no reverse edge shown — D-10). If the target was deleted, render muted **"(removed)"**, never a broken link.
  - **Photo (custom field):** a single thumbnail tile that opens the lightbox (S18); distinct from the entity's main gallery.

### S16 — Custom-field inputs (edit, in entity forms)
- Inputs render after built-ins in schema order, same paper-shade well + hairline + radius-sm + amber-focus treatment as Phase-1 PersonForm inputs. Per type: Text → text input; Number → numeric input; Phone → tel input; Date → date input; Tags/Select → chip input (free tags) or option-constrained select (if the field defines options); Link-to-entity → a typeahead/select over the target type's entities; Photo → single-photo upload (reuse `PhotoUpload`).
- Validation is **zod type-check + the field's `required` toggle** only (D-06). A required-but-empty field on save → inline brick **"This field is required."** under that input; a type-mismatch (e.g. text in a number field) → **"Enter a number."** / **"Enter a valid date."** No min/max/regex messaging (deferred).

### S17 — Entity forms (Location / Group / Relationship-link)
- Same Radix Dialog shape, treatment, and **amber-on-create / neutral-ink-on-edit** save discipline as Phase-1 `PersonForm` (carried forward exactly). Title: **"New {type}"** / **"Edit {type}"**.
- Built-in spine per D-18: **Name** (required) + **Photo/thumbnail** + **Gallery** + **Notes** (free text). **Locations additionally** keep background image + dimensions (the promoted `MapDoc`, D-07). Then custom fields (S16).
- Footer: primary **"Create {type}"** (amber on create) / **"Save changes"** (neutral ink on edit); secondary **"Cancel"**.
- Validation: empty name → inline brick **"Add a name so you can find this {type}."** (generalizes the Phase-1 person message). Offline hint reused: **"Saved locally · will sync to Drive when reconnected."**
- Reached from the top-bar **`+ New ▾`** menu (Radix DropdownMenu offering the four types) or from a browse view's empty-state / row-overflow Edit.

### S18 — Photo lightbox
- Full-viewport overlay, dark scrim `#1B2230` @ ~92%, `elevation`-free image with a soft dark lift. Opens on any gallery thumbnail click (D-20), from ProfileSidebar gallery or a custom Photo field.
- Controls (all paper glyph buttons, ≥44px, amber focus ring): **prev** (`ChevronLeft`, left), **next** (`ChevronRight`, right), **close** (`X`, top-right). Caption bottom-center: mono index **"3 / 8"** + optional filename, paper text on scrim.
- Dismiss: **Esc**, **backdrop click**, or close button — returns focus to the originating gallery thumbnail.
- Keyboard: **← / →** navigate, **Esc** closes; focus is **trapped** in the overlay while open; prev/next wrap or disable at ends (planner's choice — contract: at a boundary the control is either disabled-with-state or wraps, never a dead no-op). No zoom/pan in v1 (D-20).
- States: **single photo:** prev/next hidden (or disabled), only close. **Loading full-res:** centered quiet shimmer on the scrim, never a blank flash. **Decode error:** paper line on scrim — **"This photo couldn't be opened."** + close.
- Motion: respects `prefers-reduced-motion` (no slide transition between photos when reduced).

### S19 — Gallery drag-to-reorder
- Active in **edit mode** of the entity (or an explicit "Reorder" affordance on the gallery). Tiles gain a `GripVertical` handle on hover/focus; drag reorders; order persists to the entity's ordered `gallery: MediaRef[]` (D-21). The **first tile is badged "Thumbnail"** (Label-13, paper-shade pill) since it acts as the entity thumbnail.
- Keyboard reorder: tile/handle focusable; **Space** picks up, **↑/↓ or ←/→** moves, **Space** drops, **Esc** cancels; each move announced via `aria-live` ("Moved photo to position 2 of 8"). This is required, not optional — drag-only would fail the carried-forward a11y bar.
- States: **drag in flight:** dragged tile lifts (elevation-2, 0.9 opacity), gap opens at the target; respects reduced-motion (instant snap, no animated shuffle). **Single photo:** no reorder affordance. Persistence is the same dirty-flag → sync path; an offline reorder shows no special UI (saved locally).

### S20 — Privacy / sensitivity notice
- One-time Radix Dialog at first run (first provider connect OR first entity creation, whichever comes first), dismissible (D-19). Paper, `elevation-2`, `radius-md`. Title (Heading-20) + Body copy + a single **"Got it"** dismiss (neutral — not amber, this is acknowledgement not creation). Re-viewable any time from nav **"ⓘ About / Privacy"**.
- Not an every-create interruption; not a buried static notice (D-19). Dismissal state persists locally (and is fine to lose — re-showing once is harmless).
- Keyboard: focus-trapped, Esc = dismiss (same as "Got it"), focus returns to a stable anchor.

### S21 — Delete-vs-remove (the user-flagged correctness fix)
Two **clearly distinct, separately-labeled** actions (D-11/D-12), never collapsed into one button:
- **"Remove from map"** — appears only when the profile/row was reached from a **marker / map context**. Neutral button (NOT brick — it is non-destructive to the entity). Deletes **only that marker**; the entity stays in the DB and in its browse list. Confirm is lightweight (or inline undo-friendly): Title **"Remove from this map?"** Body **"{Name} stays in your database and lists — only the marker on this map is removed."** Buttons **"Remove from map"** (neutral) / **"Cancel"**.
- **"Delete {entity}"** — appears in **entity / browse-list context** (row overflow, profile when opened from a list). **Brick**, full cascade (the existing `deletePerson()` logic generalized — entity + all markers across every map + unreferenced-media GC). Confirm: Title **"Delete this {type}?"** Body **"{Name} will be removed from your database and every map it appears on. This can't be undone unless you restore a backup."** Buttons **"Delete {type}"** (brick) / **"Cancel"**.
- The profile sidebar therefore shows **either** "Remove from map" (map-opened) **or** "Delete {entity}" (list-opened), and the row overflow always offers "Delete {entity}". Locations follow the same remove-from-view vs delete-the-location split (D-12).

## Accessibility & Interaction

Carries forward Phase 1's bar in full and extends it to every new surface.

**Focus & keyboard (DOM chrome):**
- Visible focus ring on every interactive control: 2px amber outline + 2px offset (unchanged) — now also on nav items, browse rows, sort toggle, field-manager controls, drag handles, lightbox controls, link-to-entity inputs.
- **Left nav (S10):** roving arrow-key focus within the nav group, Enter/Space selects a view, `aria-current="page"` on active item, Tab leaves to the main surface.
- **Browse list/rows (S11/S12):** rows are keyboard-focusable, Enter opens the profile; nested "Show on map" and overflow are independently tabbable with `stopPropagation`; virtualization must keep focus correct as rows mount/unmount (don't lose focus on scroll).
- **Field manager (S13/S14):** standard Dialog focus-trap + Esc; reorder is keyboard-operable (handle focus → ↑/↓ → `aria-live` announce); field add/edit/remove all keyboard-reachable.
- **Entity forms (S17):** same focus-trap, first-field focus, Esc-cancels, focus-returns-to-trigger discipline as Phase-1 PersonForm.
- **Lightbox (S18):** focus trapped while open; ← / → navigate; Esc / backdrop / close dismiss; focus returns to the originating gallery thumbnail. This is a hard requirement (the lightbox is fully keyboard-operable, not mouse-only).
- **Gallery reorder (S19):** Space-pickup / arrow-move / Space-drop / Esc-cancel with `aria-live` position announcements — drag is an enhancement, keyboard is the contract.
- **Privacy notice (S20):** focus-trapped, Esc = dismiss, focus returns to a stable anchor.

**Canvas selection (Konva) → AT bridge (carried forward, now reinforced):**
- The canvas remains keyboard-opaque this phase (full canvas keyboard nav still deferred to Phase 3). BUT every entity is **now reachable by keyboard via its browse list** (S11) — the browse list is the accessible, non-canvas path to every entity that Phase 1 lacked. Selecting a marker still opens the profile + moves focus + announces "Selected {Name}" (unchanged).
- "Show on map" jumps the Map view to the entity's marker and announces the move via `aria-live`; for AT users this is a labeled DOM action, not a canvas-only gesture.

**States coverage (every new surface declares):** loading (shimmer, never blocking), empty (directive copy + the single amber create CTA), error (problem + fix in interface voice), offline (full function from Dexie, reassurance copy). No spinner-only dead-ends — carried forward verbatim.

**Motion:** respect `prefers-reduced-motion` — lightbox photo transitions, gallery reorder shuffle, row hover lift, and shimmer all reduce to static/instant states. Restrained animation overall (carried forward).

**Targets:** all icon-only controls ≥44px (nav items, show-on-map, lightbox prev/next/close, drag handle, overflow). Browse row hit area is the full 64px row.

**Security (carried forward, load-bearing):** ALL user-entered custom-field values, entity names, notes, link labels, and tags render as **React children — never `dangerouslySetInnerHTML`** (T-03-01: an XSS here could exfiltrate the Drive access token). This is a hard rule for every new rendering surface (S12, S15, S18 caption).
