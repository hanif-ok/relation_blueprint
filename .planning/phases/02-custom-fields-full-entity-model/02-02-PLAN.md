## Phase Goal

**As a** single curator, **I want to** model my world fully — defining custom typed fields on any entity and working with all four first-class object types — and browse people and locations as lists, **so that** my whole world is captured in rich, typed records I fully own.

## Acceptance Criteria (this plan — the delete-vs-remove correctness fix)
- [ ] "Remove from map" (marker context) deletes only the marker; the person stays in the DB.
- [ ] "Delete {entity}" (list context) removes the entity + all its markers + GCs unreferenced media.
- [ ] The GC sweep keeps a blob alive if any surviving entity (any type, incl. custom Photo value) references it.
- [ ] Deleting a Group / Location / Relationship-link cascades correctly through the generalized path.

<objective>
Fix the user-flagged delete-from-map bug and generalize delete semantics across the full entity model. Today `deletePerson()` (repository.ts:84) is the only delete and it always cascades — so removing a person from the map wrongly deletes them from the database. This plan splits that into two clearly distinct actions per D-11/D-12: a marker-only `deleteMarker` (the map-level "Remove from map", neutral, non-destructive to the entity) and a generalized `deleteEntity` cascade (the list-level "Delete {entity}", brick, full removal + media GC). The media GC sweep is generalized to scan every entity type's photo/gallery/background AND custom Photo-field values so a shared blob is never wrongly collected. The ProfileSidebar shows exactly one of the two actions based on whether it was opened from a marker or from a list.

Purpose: This is a required behavior change the user raised as high priority, and it is the correct foundation for Phase 3's MAP-05 (one person on multiple maps — removing from one map must leave them on the others and in the DB). It is a thin, self-contained vertical slice: a real user can now remove a marker without losing the entity, and delete an entity for real from its profile.
Output: `deleteMarker` + generalized `deleteEntity` (with `deletePerson` delegating to it), the dual-action ProfileSidebar, and the cascade/GC unit + E2E tests.
</objective>
