## Phase Goal

**As a** single curator, **I want to** model my world fully — defining custom typed fields on any entity and working with all four first-class object types — and browse people and locations as lists, **so that** my whole world is captured in rich, typed records I fully own.

## Acceptance Criteria (this plan — the multi-surface shell + browse + create + privacy)
- [ ] Left nav swaps Map vs four browse lists; arrow-key roving focus; active item not amber.
- [ ] "+ New" creates all four entity types; each appears in its browse list (DATA-01).
- [ ] Browse People and Locations (and Groups, Relationship-links) as lists; row opens profile (BRWS-01/02).
- [ ] Name A-Z default + "Recently updated" toggle; lists stay smooth toward thousands of rows.
- [ ] One-time privacy notice at first run, re-viewable from the nav (criterion 4).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user text (name, tags, secondary line) -> browse-row + nav render | New high-volume render surfaces for user-controlled text across four entity types |
| entity media -> per-row thumbnail object URLs | Lazy per-row media loading must revoke object URLs to avoid leaks at thousands of rows |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure (XSS) | BrowseRow name/secondary line, ViewSwitcher labels, EntityForm fields | mitigate | All user text rendered as React children — never `dangerouslySetInnerHTML` (an XSS could exfiltrate the in-memory Drive token) |
| T-03-04 | Denial of Service (memory) | Browse lists at thousands of rows + per-row media URLs | mitigate | Constant 64px-row virtualization + Dexie indexed `orderBy` queries + per-row `resolveMediaUrl` revoked on scroll-out/unmount (U3) |
| T-03-05 | Tampering | Show-on-map / nav targeting a non-existent or wrong-type entity | mitigate | Show-on-map disabled-with-reason for non-spatial types; view targets resolve through live Dexie reads, not assumed ids |
</threat_model>
