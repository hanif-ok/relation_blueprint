## Decisions Made

- **Sync-local token, not a widened EntityType.** `SyncShardType = EntityType | 'field-defs'` lives in `syncEngine.ts`. The core `EntityType` union in `src/domain/types.ts` is verbatim unchanged (still the five entity families), confirmed by `tsc` showing no exhaustiveness errors leaking into the field-manager/profile UI.
- **Optional manifest pointer.** `'field-defs'` is `.optional()` in `ManifestSchema`; a present pointer is still fully `ShardPointerSchema`-validated (threat T-02.1-01 gate stays strict). Old manifests parse clean and reconcile no-ops.
- **No database migration.** `db.fieldDefs` already exists (Dexie `version(2)`); Dexie auto-upgrades in-browser. NO `drizzle-kit push` / `prisma db push` / `payload migrate` / migration task was introduced — consistent with the project MEMORY.md known false-positive on this Dexie schema file.
- **Lowest-blast-radius resolver.** Kept the existing `SHARD_NAMES.fieldDefs` camelCase property (referenced by serialize/deserialize) and added a `'field-defs'` kebab alias so the engine indexes `SHARD_NAMES['field-defs']` without touching the serializer's read/write paths.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Switched `markSynced`/`upsert` Dexie transactions to array form**
- **Found during:** Task 1 (GREEN wiring)
- **Issue:** Adding `db.fieldDefs` to the `upsert` positional-arg transaction pushed it to 8 arguments; Dexie's `transaction(mode, ...tables, fn)` overload caps at 7 (TS2554: "Expected 3-7 arguments, but got 8").
- **Fix:** Converted both `markSynced` and `upsert` to the array-of-tables transaction form (`db.transaction('rw', [t1, ...t6], fn)`), which is unbounded.
- **Files modified:** src/sync/syncEngine.ts
- **Verification:** `npx tsc --noEmit` exits 0; full suite green.
- **Committed in:** 52ff8bf (Task 1 GREEN commit)

**2. [Rule 1 - Bug] Test isolation: clear `db.meta` watermarks to simulate a fresh device**
- **Found during:** Task 1 (GREEN verification)
- **Issue:** The round-trip test shared one Dexie `db` between "device A" and "device B". Device A's `setShardMeta('field-defs', now)` persisted in `db.meta`, so device B's reconcile saw `now <= now` and skipped the pull — `db.fieldDefs.get('f1')` came back undefined.
- **Fix:** Device-B simulation now clears `db.meta` (and `db.fieldDefs`) before reconcile, exactly as a brand-new Dexie would present, matching the established pattern in `reconcile.test.ts` (which calls full `clearDb()` between devices).
- **Files modified:** tests/sync/reconcile.fieldDefs.test.ts
- **Verification:** All 4 cases in the file pass.
- **Committed in:** 52ff8bf (folded into Task 1 GREEN commit)
