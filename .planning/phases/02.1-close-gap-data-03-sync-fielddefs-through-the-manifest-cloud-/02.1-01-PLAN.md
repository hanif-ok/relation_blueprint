<objective>
Close the DATA-03 cloud-sync BLOCKER: custom-field DEFINITIONS (`db.fieldDefs`) are serialized into `field-defs-000.json` but never pushed to or pulled from the cloud, because the sync engine's hand-listed entity-type machinery omits `'field-defs'`. On a second device or a fresh-session reconnect, entity custom VALUES arrive with no DEFINITIONS to render or validate them — breaking the "own your entire database in your own cloud" guarantee for the custom-field schema.

The fix is symmetric, not novel: add the sixth `field-defs` branch everywhere the five entity types are hand-listed in `src/sync/syncEngine.ts`, add ONE optional pointer to `ManifestSchema`, and prove it with a push→fresh-reconcile round-trip regression test.

Purpose: Restore cloud durability for the custom-field schema (DATA-03), making STOR-02 ("entire database") literally true and STOR-03 (reconcile-on-open) complete for field definitions.
Output: Updated sync wiring + manifest schema + a new regression test file, all green.

Authoritative spec: `.planning/v1.0-MILESTONE-AUDIT.md` (the BLOCKER detail at lines 220-231) and `.planning/phases/02.1-close-gap-data-03-sync-fielddefs-through-the-manifest-cloud-/02.1-RESEARCH.md` (file:line change list, the SyncShardType token decision, backward-compat zod pattern, regression-test sketch).
</objective>
