<objective>
Generalize the single-map skeleton into an active-map editor and ship the first user-visible slice of navigation: a toolbar map switcher (D-05) with a '+ New map' quick-create entry point (D-18, complementing the Locations '+ New' and the portal-drop inline create in 03-06), a parent-chain breadcrumb (D-10/MAP-07), image-space marker anchoring composed through the background transform (RESEARCH Pattern 7), and viewport culling baked into the render path from the start (criterion 5 / RESEARCH Pattern 5). After this plan a user can hold multiple maps, switch between them, and walk a hierarchy — capability they did not have before.

Purpose: `MapView` currently hard-codes `maps[0]`. Every later editor surface (tools, layers, portals, person picker) needs an active-map model and the coordinate composition to exist first. Culling must be designed in now, not retrofitted (RESEARCH research-flag mandate).
Output: `coords.ts`, `useViewportCulling.ts`, `MapSwitcher`, `Breadcrumb`, a generalized `MapView`, lifted active-map state in `App.tsx`, and tests.
</objective>
