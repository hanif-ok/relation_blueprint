This plan (Wave 0) creates the following symbols that all later plans consume. The plan-review-convergence source-grounding pass MUST treat these as newly-created (not drift):

**New interfaces (src/domain/types.ts):**
- `BackgroundTransform` — `{ offsetX: number; offsetY: number; scale: number; rotation: number }`
- `Shape` — a drawing primitive descriptor (id, layerId, kind: 'rect'|'ellipse'|'line'|'polygon', geometry, preset, fill, rotation, optional label → zone)
- `Zone` — represented as a `Shape` carrying a non-empty `label` (D-02: a zone is a styled+labeled shape, NOT a separate type/array). No separate `Zone` interface is introduced unless the executor finds it cleaner; if introduced it must be a `Shape` alias, not a new EntityType.
- `Layer` — `{ id: string; name: string; visible: boolean; locked: boolean; order: number }`
- `MarkerKind` — `'person' | 'portal'`

**Extended interfaces:**
- `Marker` gains: `kind: MarkerKind`, `personId?: string` (now optional), `targetMapId?: string`, `width?: number`, `height?: number`, `rotation?: number`. Existing `x`/`y` are REINTERPRETED as image-space (same fields, no rename).
- `MapDoc` gains: `parentId?: string`, `backgroundTransform?: BackgroundTransform`, `shapes: Shape[]`, `layers: Layer[]` (and `zones` folded into `shapes` per D-02).

**New zod schemas (src/domain/schemas.ts):** `BackgroundTransformSchema`, `ShapeSchema`, `LayerSchema`, `MarkerKindSchema`; extended `MarkerSchema`/`MapDocSchema`.

**Extended repository (src/db/repository.ts):** `UpsertMarkerInput` + `upsertMarker` accept `kind`/`targetMapId`/`width`/`height`/`rotation`. `UpdateMapPatch` automatically covers the new MapDoc fields (it is `Partial<Omit<MapDoc,...>>`).

**Dexie upgrade:** `version(4)` block in `src/db/schema.ts`.

**New token:** `colors.portal = '#3E6B8C'` and the zone preset palette in `src/app/tokens.ts`.

**Test fixtures:** `tests/_fixtures/syntheticMarkers.ts` (generates ~1000 markers for the perf spike consumed by a later plan).
