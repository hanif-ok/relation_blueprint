# Phase 3 — UI Design Contract

> Visual and interaction contract for the spatial map editor. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> This phase **extends** the established Phase-1 visual language ("the lit field map") — it introduces no new design system, only new surfaces (tool palette, layers panel, breadcrumb, portal glyph, map switcher, person picker) built from the existing tokens. All values below either reuse `01-UI-SPEC.md` / `src/app/tokens.{ts,css}` verbatim or extend them where Phase 1 left a reserved seam.

---

## Design Direction (carried forward, unchanged)

**"The lit field map."** The map is the hero and stays dark (`#1B2230` slate Konva Stage); the chrome is warm paper (`#F4F1EA`); a single amber (`#C8742B`) is reserved for *placement and selection only*. Phase 3 adds editor chrome (tool palette, layers panel, breadcrumb) **on top of** this — all paper chrome, none of it competing with the canvas, none of it claiming amber. The signature round photo-avatar marker is unchanged; it now also gains resize/rotate handles and an optional name label.

Phase 1 explicitly reserved two seams this phase now cashes in:
- **Portal markers get a distinct non-round shape in a different reserved color** (`01-UI-SPEC.md` Forward-Looking Notes) — so amber stays selection-only.
- **Entity-type/edit chrome stays quiet ink-tints, never another saturated accent.**

## Design System

| Property | Value |
|----------|-------|
| Tool | **none** (deliberate — carried from Phase 1 Assumption A1; no shadcn/Material). Tokens are the single source of truth. |
| Preset | not applicable |
| Component library | none mandated. Headless **Radix UI primitives** permitted *only* for accessible Dialog (target picker, create-map), DropdownMenu (map switcher, tool overflow), Popover (style/picker popovers), and focus-trap behavior. They ship unstyled — all visuals from the tokens below. (Carried from A2.) |
| Icon library | **Lucide** (`lucide-react`), stroke **1.75px**. New glyphs this phase: `MousePointer2` (Select), `Square` (Rect), `Circle` (Ellipse), `Minus`/`Slash` (Line), `Pentagon` (Polygon), `DoorOpen` (Portal tool), `UserPlus`/`Users` (Person), `Layers` (panel), `Eye`/`EyeOff` (show/hide), `Lock`/`LockOpen` (lock), `ChevronRight` (breadcrumb), `Tag` (zone label). |
| Font | Display/entity-name: **Fraunces**. Body/UI/data: **Inter**. Mono (IDs, counts, "synced 2m ago"): **JetBrains Mono**. Self-hosted via `@fontsource` (offline-first). |

**Styling approach:** CSS custom properties (`src/app/tokens.css`) on `:root` + CSS Modules per component. Konva objects read the same hex values from `src/app/tokens.ts` so canvas and DOM never drift (A5). **All new canvas colors below MUST be added to BOTH `tokens.ts` and `tokens.css`** (portal hue, zone preset palette, layer-lock dimming) — never inline a hex in a component.

**No `dangerouslySetInnerHTML`.** Zone labels and marker name labels render as React / Konva `Text` only (XSS could exfiltrate the Drive token — threat T-03-01).

## Spacing Scale

8-point scale (all multiples of 4) — unchanged from Phase 1, reused verbatim:

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Tool-button icon gaps, breadcrumb chevron gaps, layer-row inner padding |
| sm | 8px | Layer-row vertical rhythm, toolbar button gaps, picker list-item padding |
| md | 16px | Layers-panel padding, toolbar horizontal padding, popover padding |
| lg | 24px | Panel section padding, map-switcher dropdown padding |
| xl | 32px | Layers-panel ↔ canvas separation, group separation |
| 2xl | 48px | Empty-state vertical rhythm (inherited) |
| 3xl | 64px | Page-level breathing room (inherited) |

**Exceptions:**
- **Icon-only controls** (tool buttons, layer eye/lock toggles, breadcrumb crumbs) keep a **minimum 44px hit area** even when the glyph is 20px — accessibility, not a scale value.
- **Touch parity (D-19):** on coarse-pointer devices (`@media (pointer: coarse)`), interactive tap targets are **≥ 44px** and tool-palette buttons grow to **48px**. Konva **Transformer anchor handles are 24px** on touch (vs. 12px default) with a **44px enlarged hit area** (`anchorSize` + larger hit rect) so fingers can grab them.
- Top bar height fixed at **56px** (inherited). Editor toolbar strip height **48px**.

## Color

Dark canvas + warm paper chrome + one reserved amber + **one newly-cashed reserved portal hue**. Phase 3 ships light paper chrome over the permanently-dark canvas (unchanged).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F4F1EA` (warm paper) | All DOM chrome: top bar, editor toolbar, layers panel, popovers, pickers, sidebar |
| Canvas surface | `#1B2230` (deep slate) | The Konva Stage behind maps — content, not chrome (not counted in the 60/30/10 split) |
| Secondary (30%) | `#E7E2D6` (paper-shade) | Layer rows, tool-button rest fill, picker list wells, zone-label chips, hover fills |
| Accent (10%) | `#C8742B` (amber) | **Selection only** — see reserved list below |
| Destructive | `#B23A2E` (brick) | Delete layer / delete map / delete shape confirmation only |
| Ink (text) | `#26211A` primary / `#6B6358` muted | Body and label text on paper |
| **Portal hue (NEW)** | `#3E6B8C` (slate-blue) | **Portal glyph fill only** — a calm cool blue that reads as "doorway/elsewhere", distinct from amber selection and from any entity tint. Reserved exclusively for portal markers. |

**Accent (amber `#C8742B`) reserved exclusively for** (carried + extended):
1. The **selected object's** Transformer handle outline + the selected marker's ring/pin-stem on the canvas (D-14/D-15).
2. The **active tool** in the tool palette (the one tool currently armed) — amber 2px underline/left-bar on the active mode button.
3. The marker **placement** affordance (drop-here ghost while placing a person or portal).
4. The focus ring on interactive DOM controls (2px amber + 2px offset).

Amber is **never** used for: the `+ New` button is amber *only* for the create-entity action (inherited from Phase 1's `+ Person`), tool buttons at rest, layer rows, breadcrumb crumbs, the map switcher, generic hovers, or decorative fills.

**Portal hue (`#3E6B8C`) reserved exclusively for** the portal glyph body. When a portal is *selected*, it keeps its slate-blue fill but gains the **amber** Transformer/selection outline (selection is always amber, identity is always the hue). This keeps the two color meanings orthogonal.

**Zone / shape preset palette (D-03 — Claude's discretion, prescribed here).** A small curated set of **muted, low-saturation tints** chosen to sit *under* markers without competing with amber/portal-blue or fighting the dark canvas. Each is used as a translucent fill (default **20% opacity**) with a solid 1.5px stroke of the same hue at full opacity:

| Preset | Stroke hex | Fill (20%) | Suggested use |
|--------|-----------|-----------|---------------|
| Stone (default) | `#8A8170` | `rgba(138,129,112,0.20)` | Generic rooms / unlabeled areas |
| Sage | `#6E8E6A` | `rgba(110,142,106,0.20)` | Outdoor / green areas |
| Clay | `#A8745A` | `rgba(168,116,90,0.20)` | Warm/living spaces |
| Dusk | `#6E7A9E` | `rgba(110,122,158,0.20)` | Cool/utility spaces |
| Plum | `#8A6E8E` | `rgba(138,110,142,0.20)` | Restricted/special zones |

A **fill on/off toggle** (D-03): off = stroke-only outline (for walls/paths drawn with the Line tool, fill is always off). **No** full color-picker / stroke-width / opacity slider / dashed-line engine (out-of-scope boundary). These five presets + on/off is the whole styling surface.

**Layer-lock dimming:** a *locked* layer's objects render at **60% opacity** on the canvas and are non-interactive; a *hidden* layer is not rendered. The lock/hide state shows on the layer row via Lucide `Lock`/`EyeOff` glyphs in ink-muted.

Contrast: all paper text pairs meet WCAG AA (ink `#26211A` on paper ≈ 11:1; muted on paper ≈ 4.6:1). White on portal-blue `#3E6B8C` ≈ 5.0:1 (AA for the glyph's inner door icon). White on amber/brick unchanged from Phase 1.

## Portal Glyph (canvas spec — the new signature object)

Drawn on the Konva Stage as a `Group`, NOT in CSS. Deliberately **NOT round** (round = person, per D-06) and in the reserved **portal-blue** hue.

| Property | Value | Notes |
|----------|-------|-------|
| Shape | **Rounded-corner diamond / doorway** — a 44px tall vertically-elongated rounded rect rotated to a soft diamond, OR a door arch silhouette. Pick the door-arch: a `radius-md`-cornered upright rect (32×44px) with an inner `DoorOpen`-style notch. The point: instantly distinguishable from a 48px circle at a glance. | D-06 distinctive unique shape |
| Fill | Portal-blue `#3E6B8C` | The one place portal-blue lives |
| Inner icon | Paper `#F4F1EA` door/arrow mark, centered | "go elsewhere" affordance |
| Default outline | 2px paper `#F4F1EA` + subtle drop shadow `0 1px 3px rgba(0,0,0,.45)` | Legible on dark canvas (mirrors marker ring) |
| Selected | amber Transformer outline + amber `0 0 0 4px rgba(200,116,43,.30)` glow | Selection is ALWAYS amber (D-07 single-click selects) |
| Hover | cursor → pointer + subtle paper outer glow; tooltip shows target map name | Affordance for "double-click to travel" |
| Target label | optional small paper-shade chip below glyph showing the target map name (follows the marker-label toggle, default hidden) | Keeps canvas clean (D-20 parity) |

## Per-Surface Component Specs & States

### S10 — Editor tool palette (D-17)
- Paper toolbar strip (or vertical rail — planner's layout discretion, keep within paper chrome). Buttons, left→right: **Select (default)** · Rect · Ellipse · Line · Polygon · Portal · Person.
- Each is an icon button (Lucide, 20px glyph, 44px hit / 48px touch) with a visible **Label** (13px/600) on wide viewports and `aria-label` always.
- **Active tool** gets a 2px **amber** left-bar/underline + paper-shade fill; rest buttons are ink glyph on transparent, paper-shade on hover. **Select is the default armed mode.**
- A mode is "armed" until the user picks another or completes a one-shot placement (Person/Portal return to Select after one drop; Rect/Ellipse/Line stay armed for repeated draws; Polygon stays armed until double-click/Enter closes the path).
- **Keyboard:** each tool has a single-key shortcut shown in its tooltip (V Select, R Rect, O Ellipse, L Line, P Polygon, T porTal, M Mark person) — optional but recommended; arrow-key roving focus within the palette group (one tab stop).
- **States:** disabled-with-reason when no active map exists (tooltip "Open or create a map first"); empty-map state defers to the Phase-1 upload affordance on the canvas.

### S11 — Layers panel (D-04)
- Paper panel docked right of the canvas (below the toolbar), `radius-md`, `elevation-1`, collapsible to an icon (`Layers`) on narrow viewports.
- Title row: **"Layers"** (Heading 20px) + `+ New layer` (neutral paper button — NOT amber).
- Each **layer row** (paper-shade well, `radius-sm`, 44px min height): drag-handle (reorder) · layer name (Body 16px, inline-editable on double-click) · trailing **show/hide** (`Eye`/`EyeOff`) and **lock/unlock** (`LockOpen`/`Lock`) icon toggles (44px hit) · optional object-count mono pill.
- Layers hold **both shapes AND markers** (D-04). Assigning: the currently-selected object's layer is shown; a small layer dropdown in the style popover (S17) or a right-click "Move to layer" moves it. New objects land on the active/selected layer.
- **Reorder** = drag rows; canvas z-order follows panel order (top row = topmost). Reduced-motion: no drag animation, instant reorder.
- **States:** empty (a fresh map) shows a default **"Markers"** layer + muted hint "Add a layer to group rooms and zones."; locked-layer rows visually dim their toggles' affordances; a layer can't be deleted if it's the only one (the action is disabled with tooltip).

### S12 — Breadcrumb bar (D-10)
- Inline paper strip in/above the toolbar: `Street ▸ Building ▸ Floor 2` using Lucide `ChevronRight` separators (ink-muted) and Body 16px crumbs.
- Each ancestor crumb is a button → navigates **up** to that map (sets it active). The current (last) crumb is ink, non-interactive, `aria-current="page"`.
- Only shown when the active map **has a parent chain** (D-09 per-map parent pointer); a top-level map shows just its own name (no chevrons).
- **Down**-navigation is via portals / child-map glyphs on the canvas (D-10) — the breadcrumb is up-only.
- **States:** deep chains truncate the middle with an overflow `…` crumb (opens a dropdown of skipped ancestors) rather than wrapping; loading a parent shows the crumb in mono-muted "…" briefly.

### S13 — Map switcher (D-05)
- Radix DropdownMenu trigger in the toolbar showing the active map name + `⌄`. Opens a searchable list of all maps/locations (reuses the Phase-2 Locations data).
- Selecting a map sets it active (generalizes `MapView` from `maps[0]`). Includes a `+ New map` item at the bottom (D-18) → create-map dialog.
- Maps also open from the **existing Phase-2 Locations browse list** "show on map" action (D-05) — the switcher is the in-editor quick path, not the only path.

### S14 — Portal glyph
See **Portal Glyph** canvas spec above. Created via the Portal tool (S10) → placement ghost → drop → target picker (S15).

### S15 — Portal target picker (D-08, D-18)
- Opens on portal drop. Radix Dialog/Popover, paper, `elevation-2`, `radius-md`. Title **"Where does this portal go?"**
- Body: a searchable list of existing maps/locations + a prominent **"Create a new map…"** option (inline create — name + optional background image, reuses the create-map flow). Choosing either sets the portal's target.
- **States:** empty search → "No maps match. Create a new one?"; cancel (Esc / Cancel) removes the just-dropped portal (don't leave a target-less portal).

### S16 — Person picker (D-11)
- The **"place person"** flow: arm the Person tool (or a dedicated control) → a paper searchable popover lists existing people (avatar thumb + name) → pick one → a placement ghost follows the cursor → click/tap drops a marker on the active map.
- This creates a **new `Marker` row** for that `personId` on this `mapId` (multi-placement; identity stays canonical, D-13). The same person can be placed on many maps.
- **States:** empty (no people yet) → muted "No people yet. Create one with + New." with a shortcut to the create-person form; searching filters live.

### S17 — Shape/zone style popover (D-02, D-03)
- Opens when a shape/zone is selected (or right-click → style). Paper Popover, `radius-md`. Contents:
  - **Preset palette** (5 swatches: Stone/Sage/Clay/Dusk/Plum) — single-select, current shown with an amber selection ring.
  - **Fill** on/off toggle (off = outline only; forced off for Line).
  - **Label** text input (optional) → renders the zone name as a Konva paper-shade chip centered on the shape (D-02 a zone is a styled+labeled shape, NOT an entity).
  - **Move to layer** dropdown.
- **No** color picker / stroke width / opacity / dashes (deferred, D-03).

### S18 — Transformer handles (D-14, D-15)
- A Konva **Transformer** attaches to the **single selected object** (person-marker, portal glyph, or shape/zone — uniform treatment, D-14) giving **resize + rotate** handles. Background image is also transformable (D-16, see below).
- **Single-select only** (D-15): click/tap an object → handles appear; click/tap empty canvas → deselect. Multi-select/marquee is deferred.
- Handle styling: **amber** anchor outlines + rotate handle (selection is always amber). Anchors **12px desktop / 24px touch**, with an enlarged 44px hit area on `pointer: coarse` (D-19).
- Persistence: new `Marker` fields **width, height, rotation** (or uniform `scale` + `rotation`) persist on `onTransformEnd` through `upsertMarker` (the marker has none today). Shapes/zones persist their geometry + rotation likewise. **Survives reload and export/restore round-trip** (criterion 6).
- **Rotating a round avatar is visually moot but harmless** (criterion 6 says "resize and rotate") — keep the rotate handle for uniformity.
- **Reduced motion:** no transform animation; handles snap.

### S16b / Background-image transform (D-16, criterion 7 — coordinate model prescribed)
- The **background image is a transformable object** (resize + rotate via its own Transformer when the canvas is in a "transform background" affordance — e.g. selecting the background with the Select tool when no object is hit, or an explicit "Edit background" toggle to avoid accidental grabs).
- **Coordinate model (Claude/research discretion → PRESCRIBED): markers are anchored in IMAGE space, not stage space.** Store each marker's `x/y` as **coordinates relative to the background image's intrinsic (untransformed) pixel space**. The canvas renders markers by composing the image's current transform (translate/scale/rotate) onto each marker's image-space coordinate. **Result: re-fitting/resizing/rotating the background keeps every placed person in the same physical spot** (the lobby person stays in the lobby — the recommendation flagged in D-16).
  - The image transform (offset, scale, rotation) persists on the `MapDoc` (or its background descriptor) and round-trips through storage/export.
  - This is a **migration-relevant model change**: existing Phase-1 markers stored in stage coordinates must be reinterpreted as image-space on the version upgrade (planner: handle in the Dexie `version(n)` upgrade + serializer; markers placed before a background transform existed are 1:1 image-space at scale 1, identity transform — so no visible move on upgrade).
- **States:** entering background-transform mode dims the markers slightly and shows a hint chip "Transforming background — markers stay anchored."; exiting commits.

### S4 — Profile sidebar (extended, D-12)
- Existing Phase-1 sidebar gains an **"Appears on:"** section: an eyebrow label (13px/600 uppercase) + a list of every map this person is placed on, each row a button → sets that map active and **focuses/centers that placement** (extends Phase-2 D-16 "show on map").
- Reinforces criterion 4 (one canonical record): editing the person's photo/name here updates **every** placement's avatar across all maps (identity is shared; only x/y/size/rotation are per-placement, D-13).
- **States:** placed on one map → single row; placed on many → list; placed on none (person exists but unplaced) → muted "Not placed on any map yet." with the place-person hint.

## Performance & Interaction Contract (criterion 5 — no jank at many markers)

This is a **load-bearing** part of the contract (RESEARCH "Pattern 5" lands here; the Phase-3 research flag mandates building it in from the start, not retrofitting):

- **Viewport culling:** only render Konva nodes whose bounding box intersects the current visible Stage rect (+ a margin). Off-screen markers/shapes/portals are not added to the layer.
- **Shape caching:** cache static/complex nodes (`node.cache()`) — especially circular-clipped avatars and zone shapes — so they don't re-rasterize every frame during pan/zoom.
- **Layer separation:** background image on its own non-listening layer (`listening={false}`, already done); markers/shapes/portals on interactive layer(s); the Transformer on its own overlay layer so selecting doesn't redraw everything.
- **Label cheapness (D-20):** marker name labels **default hidden** and are a layer/view toggle — drawing thousands of `Text` nodes is the expensive path, so off by default.
- **Hidden/locked layers** skip rendering / hit-testing entirely (free perf lever the user controls).
- **Target:** smooth pan/zoom/drag (no perceptible jank) with **hundreds of markers** on a typical map; degrade gracefully toward thousands (project scale constraint).

## Touch & Desktop Parity Contract (D-19 — deliberate scope)

Full finger parity is a user-chosen requirement. The contract:

- **Gesture disambiguation:** in **Select** mode, one-finger drag on empty canvas = pan; one-finger drag on an object = move; pinch = zoom; tap = select; double-tap on a portal = navigate. In a **draw** mode (Rect/Ellipse/Line/Polygon), one-finger drag = draw the shape (pan is suppressed; a two-finger drag still pans). Document this state machine in the planner.
- **Hit targets:** all interactive canvas objects ≥ 48px hit area on `pointer: coarse`; Transformer anchors enlarged to 24px visual / 44px hit.
- **Konva pointer handling:** use unified pointer events (`onTap`/`onDblTap` alongside `onClick`/`onDblClick`, already partly present in `AvatarMarker`); set `hitStrokeWidth` generously on thin Line shapes so fingers can grab them.
- **No hover-only affordances:** anything reachable by hover (tooltips, "double-click to travel") must also be reachable/announced without hover (long-press tooltip or visible label).

## Accessibility & Interaction

**Focus & keyboard (DOM chrome):** all new DOM surfaces (tool palette, layers panel, breadcrumb, map switcher, pickers, popovers) follow Phase-1 rules:
- Visible **2px amber focus ring + 2px offset** on every interactive control.
- Tool palette = one tab stop with arrow-key roving focus; layers panel rows arrow-navigable; breadcrumb crumbs are buttons in tab order.
- Radix DropdownMenu/Dialog/Popover provide focus trap, Esc-to-close, roving focus, focus-return-to-trigger.
- Inline-rename (layer name) commits on Enter/blur, cancels on Esc.

**Canvas selection → AT bridge (extends Phase-1 pattern):**
- The Konva canvas remains largely AT-opaque. Selecting any object announces it via `aria-live="polite"` ("Selected portal to {map}", "Selected {Name}", "Selected zone {label}").
- **Marker selection** still opens/focuses the profile sidebar (Phase-1 bridge).
- Phase-1 deferred full canvas keyboard nav (tabbing between markers) to Phase 3 *because many markers arrive here* — **at minimum** provide: arrow-key nudge of the selected object, Delete/Backspace to remove the selected object (with the destructive rules above), and Escape to deselect. A roving "next/previous object" keyboard traversal is recommended; if full traversal is deferred, the **Locations list + person picker + "Appears on"** remain the keyboard-reachable paths to every object.

**States coverage:** every new surface declares loading (mono "…"/shimmer, never blocking), empty (directive copy above), error (problem + fix in interface voice), offline (saved-locally reassurance, full function). No spinner-only dead-ends.

**Motion:** respect `prefers-reduced-motion` — placement-ghost pulse, layer-reorder drag, and any transform tweening reduce to static/instant. Marker and object drag have no inertia.

**Targets:** all icon-only controls, canvas object hit areas, and Transformer handles meet ≥ 44px (≥ 48px touch).

## Data-Model Notes for the Planner (visual contract dependencies)

These visual decisions impose data shape (planner owns the exact schema, but the contract requires them to persist + round-trip through the sharded manifest and export/restore — the cloud is the only copy):

- **Marker transform:** add `width`/`height`/`rotation` (or `scale`+`rotation`) to `Marker` — consumed by `AvatarMarker` and the portal glyph; persisted on `onTransformEnd`. Markers store coordinates in **image space** (see S16b).
- **Portal marker:** a marker variant (or a sibling object) carrying a `targetMapId` + the portal-blue glyph; distinct from person-markers and from Phase-4 relationship connectors (don't conflate — keep a connectors layer slot open).
- **Shapes/zones:** geometry + preset id + fill on/off + optional label + layer id. May live as a new shard family (extends `EntityType`/`ManifestSchema`/serializer/SyncEngine six-branch wiring) OR as sub-objects on the `MapDoc` — planner tradeoff; either way the **manifest swap stays the sole atomic commit point**.
- **Layers:** per-map, ordered, name + show/hide + lock; objects reference their layer id.
- **Map hierarchy:** a per-map `parentId` pointer (D-09) — every level is a Map/Location (no new container type).
- All of the above must be added to the **type ↔ schema ↔ Dexie triple** preserving the `satisfies` locks, and serialize for export/restore.
