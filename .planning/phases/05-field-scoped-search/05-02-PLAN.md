<objective>
Deliver the signature field-scoped-search behavior (SRCH-02): a field-scope checkbox panel in the Search view, defaulting to all fields ON and subtractive, so the user can uncheck a field (e.g. a custom "Job" field) to exclude its matches — "smith" then matches names but not blacksmiths' jobs. The selection persists across sessions keyed by stable field id, the panel derives live from the People field schema, and the index is extended to every searchable custom attribute so those checkboxes have something to scope.

Purpose: Make the scoping mechanism real and visible (D-03/D-04/D-05) — the blacksmith example is the whole point of the phase. The checkboxes drive the query-time field restriction seam that plan 01 built.
Output: A persisted scope hook + resolver; a native checkbox ScopePanel; the index extended to custom fields (D-03); the all-fields-off guard state (D-11); a unit test for the subtractive/persistence/rename rules; an e2e proving the smith-vs-blacksmith behavior.
</objective>
