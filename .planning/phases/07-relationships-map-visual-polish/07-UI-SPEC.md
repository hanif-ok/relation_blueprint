# Phase 7 — UI Design Contract

> Visual and interaction contract for a **viewer-only polish** phase extending the already-shipped Phase 3 map (Konva) and Phase 4 relationship graph (Cytoscape). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Nothing here introduces a new design system, DOM component library, or entity data. All visuals **inherit** the Phase 1 foundational token contract (`.planning/phases/01-storage-spine-first-person-on-a-map/01-UI-SPEC.md`, `src/app/tokens.ts` / `tokens.css`). This spec declares only the **deltas** the three deliverables add.

---

## Scope Anchor

Three deliverables, one per ROADMAP success criterion (CONTEXT.md D-01…D-13):

1. **Customizable map colors** — two native color pickers in the existing map `LayersPanel`: marker **name-label text** color and relationship **connector line** color. Per-map, persisted in Dexie `meta`. Structural halo/casing guarantees legibility over light AND dark background images.
2. **Draggable graph nodes** — relax `autoungrabify`; drag rearranges the layout, tap still opens the profile. Layout-only, never mutates data. Sticky-persist to the existing `graphPositions` cache + a **Reset layout** control.
3. **Dynamic ego focus** — tapping/opening a node re-lays-out the whole graph `concentric` around that ego; tapping another re-egos; an **Exit focus** control (and closing the profile) restores the saved base layout.

**Out of scope (do not add UI for):** graph edge/node-label color customization (graph stays token-driven, D-01); any relationship-editing affordance in the graph (viewer-only); cross-device sync of appearance/layout prefs (device-local `meta` only).

## Color

Inherited palette is the single source of truth (`tokens.ts`). This phase does **not** add a token. It adds **two per-map user-chosen colors** that are explicitly *content-appearance preferences*, not chrome tokens, and it **hardens legibility structurally** so any user choice reads.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F4F1EA` paper | LayersPanel background (inherited) |
| Secondary (30%) | `#E7E2D6` paper-shade | Picker row wells, connector-label pill (inherited) |
| Accent (10%) | `#C8742B` amber | **Reserved unchanged** — selection + ego only (see below) |
| Canvas surface | `#1B2230` slate | Map/graph stage (inherited, content) |

**Amber discipline (A8) — hard constraint this phase:**
- Amber stays reserved for **selection + ego emphasis only**. The selected connector stays amber (`ConnectorLayer.tsx` l.95); the ego graph node keeps its amber ring (`graphStyle.ts` `.ego`, `:selected`).
- **User-chosen colors must never be amber-role.** The customizable label/connector colors apply to the **resting (unselected)** state only. A selected connector still overrides to amber regardless of the user's chosen line color. A user literally picking amber is allowed (native picker, D-02) but the app never *assigns* amber — no collision with the reserved role.

**Customizable colors — defaults (D-06, "keep today's look"):**

| Customizable target | Default value | Element |
|---------------------|---------------|---------|
| Marker name-label text | `#F4F1EA` (`colors.paper`) | `AvatarMarker.tsx` name `Text.fill` |
| Connector line (resting) | `colors.hairline` @ 55% (`hexToRgba('#D8D2C4', 0.55)`) | `ConnectorLayer.tsx` `CONNECTOR_HAIRLINE` |

Existing databases render **identically** until the curator customizes (defaults equal today's hardcoded values), now made robust by the halo/casing below.

## Legibility Contract (D-04 — structural, not palette-restricting)

The white-on-white gap (Phase 04 UAT tests 6 & 7) is closed by rendering a **contrasting outline behind the colored element**, so *any* chosen color separates from *any* background image. The outline color is **auto-derived from the chosen color's luminance** — this is what guarantees "reads on light AND dark," since the outline is always the luminance-opposite of the mark.

**Marker name label (Konva `Text` halo):**
- Compute `isLight = relativeLuminance(chosenFill) > 0.5`.
- `stroke` = `isLight ? '#1B2230' (slate, near-black)` : `'#F4F1EA' (paper)`.
- `strokeWidth` = **2** (canvas px), `fillAfterStrokeEnabled: true` (fill paints over the stroke's inner half so the glyph keeps its color and weight), `lineJoin: 'round'`.
- Plus depth shadow: `shadowColor '#000000'`, `shadowOpacity 0.55`, `shadowBlur 3`, `shadowOffsetY 1`.
- Result: a light label gets a dark halo (reads on a light map); a dark label gets a light halo (reads on a dark map).

**Connector line (Konva cased-line — a second underlay `Arrow`):**
- Draw a **casing** `Arrow` first (same `points`, same arrowhead geometry) with `stroke`/`fill` = the luminance-opposite neutral of the chosen line color (`isLight ? slate : paper`) at ~0.6 alpha, `strokeWidth` = colored line width **+ 2**.
- Draw the colored `Arrow` on top (existing widths: 1.75 resting / 2.5 selected).
- Selected state still swaps the *top* line to amber; the casing remains (keeps the selected line legible too).
- `perfectDrawEnabled={false}`, `listening={false}` preserved (no hit-area/perf regression).

**Discretion exercised (was open in CONTEXT):** halo stroke width = 2px, shadow = black @0.55 blur 3, casing = +2px luminance-opposite @0.6 alpha. Planner may tune within "contrast guaranteed on light and dark"; the **auto-luminance-opposite rule is the non-negotiable mechanism**.

**Reduced motion / perf:** halo and casing are static paint — no motion implication. Casing doubles connector shape count; reuse the Phase-4 `listening={false}` layer and viewport patterns; connectors are already a pure per-render projection.

## Persistence Contract (D-05 — per-map, Dexie `meta`, no migration)

Reuse the established key/value `meta` pattern (`positionCache.ts`, `useScopeSelection.ts`) — **no schema migration** ([[schema-gate-dexie-false-positive]]).

| Concern | Storage | Shape |
|---------|---------|-------|
| Per-map colors (D-05) | single `meta` row, key `mapAppearance` | `Record<mapId, { labelColor: string; connectorColor: string }>` — one row, keyed internally by map id. A map absent from the record renders defaults. |
| Sticky graph positions (D-08) | existing `graphPositions` row (`positionCache.ts`) | unchanged shape; **semantics change** — a partial cache places only missing nodes (see Interaction Contracts) |

**Discretion exercised:** single `mapAppearance` row holding a `mapId → colors` map (mirrors the single-row `graphPositions`/`scopeSelection` shape) rather than N rows — simpler read/write, one live query. Both colors stored as `#rrggbb` hex strings straight from the native picker; the 55%-alpha connector default is applied at render (store the solid hex, or the sentinel "default" → falls back to `CONNECTOR_HAIRLINE`).

These prefs are **device-local and unsynced** (like `graphPositions`) — a regenerable convenience, not authored data. Not wired into the manifest/sync path this phase ([[sync-push-pull-gap-pattern]]).

## Interaction Contracts

### IC-1 — Color pickers (LayersPanel, D-02/D-03)
- **Where:** inside `LayersPanel.tsx`, in a new "Appearance" block directly beneath the existing "Show name labels" / "Relationship labels" toggles — same per-map surface, same collapse behavior.
- **Controls:** two labelled rows, each a native `<input type="color">` + a 13px/600 label + a small "Reset" text affordance:
  - Row A: **"Name label color"** → writes `mapAppearance[mapId].labelColor`, live-updates `AvatarMarker` fill.
  - Row B: **"Connector color"** → writes `mapAppearance[mapId].connectorColor`, live-updates the connector line.
- **Live feedback:** the map re-renders on `onChange` (native picker fires continuously while dragging) — the curator sees the halo/casing keep it legible in real time.
- **Reset:** per-row "Reset" clears that map's stored value → falls back to the D-06 default. No confirm (non-destructive, instantly reversible).
- **Persistence:** write on change (debounced is optional; `meta` writes are cheap). Reload restores the chosen colors for that map.
- **No error state** — a color is always valid; the halo makes every choice legible, so there is no "illegible color" failure to report.

### IC-2 — Draggable graph nodes (D-07/D-08/D-09)
- **Enable drag:** remove `autoungrabify` from `CytoscapeComponent` in `GraphView.tsx`. Cytoscape natively separates **tap** (no movement → existing `onSelectNode` → ProfileSidebar, D-12 bridge preserved) from **drag** (moves the node). No mode toggle.
- **Data safety:** dragging is **layout-only** — it must never call a repository mutation. The existing viewer-only note stays. (`boxSelectionEnabled={false}` may remain.)
- **Sticky persist:** on `dragfree`, save positions to the `graphPositions` row (extend the existing `layoutstop` save path). **Invalidation rule change (supersedes Phase-4 D-13):** when the node-set changes (a person/group added), **keep everyone's saved positions and auto-place only the newcomer** — do NOT blow away the hand-arranged layout with a fresh `cose`. `hasCachedPositions` semantics become "cache covers the existing nodes"; missing nodes get placed, cached nodes stay put.
- **Cursor:** grab/grabbing affordance on node hover/drag (Cytoscape default is acceptable).

### IC-3 — Reset layout (D-09)
- **Control:** a **"Reset layout"** `<button>` in the existing `GraphView` toolbar (beside "Relationship labels").
- **Behavior:** clears the saved manual positions (`graphPositions` row) and re-runs a fresh `cose` (`animate:false`, matching the existing Phase-4 pattern).
- **Availability:** always present; it is the escape hatch back to an automatic arrangement.

### IC-4 — Dynamic ego focus (D-10/D-11/D-12/D-13)
- **Enter focus:** opening the graph from a profile (existing `egoId` path) **or** tapping a node. A tap does BOTH: opens the profile (existing bridge) **and** re-egos + re-lays-out. "Focus follows the tap" — tapping a different node re-egos onto it.
- **Layout:** re-run **`concentric`** with the tapped node at center, all other nodes in rings by hop-distance (all nodes stay visible — whole-graph re-layout, not neighborhood-only). The ego keeps its amber `.ego` ring (`graphStyle.ts`, unchanged).
- **Transient overlay (D-12/D-13):** ego layout **never overwrites** the persisted base positions in `graphPositions`. It is a view-state overlay computed on top of the saved base.
- **Exit focus:** an **"Exit focus"** (a.k.a. "Reset view") `<button>` — **visible only while in ego focus** — restores the saved base layout (manual or `cose`), discarding nothing. Closing the `ProfileSidebar` also exits focus. Exiting does NOT clear manual positions (that is Reset layout's job — IC-3).
- **Two resets never conflate (D-13):** *Reset layout* (IC-3) discards manual positions + re-runs `cose`. *Exit focus* (IC-4) leaves the transient concentric overlay + returns to the saved base. Resting state is always the base layout; ego is a transient overlay.

**Discretion exercised (ego config, was open):** `concentric` with `animate:false` (snap, consistent with the existing `cose animate:false` and reduced-motion posture), default `minNodeSpacing` acceptable; planner may enable a short 300ms animate to echo the existing ego center/zoom animation — but must respect `prefers-reduced-motion` (snap when reduced). Re-running `concentric` per tap on a viewer-only, typically-modest graph is acceptable; reuse Phase-4 viewport-preserving patterns; watch large graphs (planner note, not a blocker).

## Accessibility & Interaction

- **Native color input:** each `<input type="color">` has an associated `<label>` (the visible field label) so it is name-reachable by screen readers and keyboard-operable natively. Wrap each in a ≥44px-tall row (swatch is ~28px). Focus ring: inherited 2px amber outline (focus indication is a permitted amber use — it is selection/focus, A8).
- **Canvas→AT bridge preserved (R7):** a graph node **tap still opens the ProfileSidebar and announces the entity** even though tap now also re-egos (D-12). Dragging must not steal the tap's selection announcement. Marker/connector color changes are visual-only; the map's AT bridge already routes selection through the sidebar (canvas is AT-opaque).
- **Keyboard for graph controls:** "Reset layout" and "Exit focus" are real `<button>`s in DOM (not canvas) — natively focusable/activatable, reachable in the toolbar tab order after the labels toggle.
- **Node dragging is pointer-only** (Cytoscape) — it does NOT become the sole path to any data or state; every node remains reachable by tap, and layout is a convenience. No keyboard drag required this phase (consistent with the Phase-1 deferral of full canvas keyboard nav).
- **Reduced motion:** `prefers-reduced-motion` → ego `concentric` re-layout and any Reset-layout `cose` **snap** (no animation); connector/label halo are static. Honor the existing reduced-motion posture.
- **Contrast:** the auto-luminance halo/casing is precisely the mechanism that keeps user-chosen label/line colors distinguishable from the background image on the AT-opaque canvas; DOM picker labels use inherited ink `#26211A` on paper (≈11:1, AA).
