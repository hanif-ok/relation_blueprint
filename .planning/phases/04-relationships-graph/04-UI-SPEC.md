# Phase 4 — UI Design Contract

> Visual and interaction contract for Relationships & Graph. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> This phase adds ZERO new foundational tokens — it inherits the locked visual language from `01-UI-SPEC.md` (`src/app/tokens.ts` + `tokens.css`). What is new is the **projection of an existing token vocabulary onto two new canvas surfaces**: data-driven map connectors and the viewer-only Cytoscape graph. Amber stays the single reserved selection color across all three surfaces (map markers, map connectors, graph nodes/edges).

---

## Design Direction (this phase's point of view)

Phase 4 makes **relationships visible without ever letting the user "draw" them.** The through-line from Phase 1's "lit field map":

- **Connectors are projections, never ink.** A line on the map is a rendered consequence of an authored relationship — the user edits it in a profile, never by dragging on the canvas (D-10). Visually the connector must read as *quieter than the markers it joins*: it lives on a dedicated layer **beneath** the marker content (D-08) so avatars always win the foreground.
- **The graph is the map's calm twin.** The Cytoscape surface inherits the same **deep-slate canvas + warm-paper nodes** as the map (Phase-1 forward note, `01-UI-SPEC.md` l.308) so the two spatial views feel like one product. Person nodes reuse the round photo-avatar signature; group nodes reuse the paper-shade type-glyph treatment already used in the profile header (U2).
- **One accent, still amber, still selection only.** The selected connector, the focused/ego graph node, and the selected edge all use amber `#C8742B` — the exact rule inherited from the marker. Direction is expressed with an **arrowhead** (a shape, not a color), so a directed relationship never spends the accent budget.
- **Authoring reuses existing surfaces.** No new panel identity: the "Relationships" section is a sibling of the "Appears on" block inside the existing `ProfileSidebar`; the relationship record itself opens as a full `ProfileSidebar` entity profile (D-06); the graph is one more `ViewSwitcher` entry (D-11).

## Color

No new foundational colors. This phase **reuses** the locked palette and — exactly like the Phase-1 marker — introduces canvas/graph *content* treatments that sit outside the 60/30/10 chrome split (the slate canvas is the hero content surface, not chrome).

| Role | Value | Usage this phase |
|------|-------|------------------|
| Dominant (60%) | `#F4F1EA` paper | Relationships-section background, add-flow surfaces (inherited chrome) |
| Canvas surface | `#1B2230` slate | The Konva map Stage **and** the Cytoscape graph background (shared hero surface — visual continuity) |
| Secondary (30%) | `#E7E2D6` paper-shade | Endpoint chips, connector/edge label pills, group-node fill, initials-fallback fill |
| Accent (10%) | `#C8742B` amber | **Selection only** — see reserved list below |
| Destructive | `#B23A2E` brick | Delete-relationship action + its confirmation only |
| Ink / muted | `#26211A` / `#6B6358` | Row text on paper; edge-label text |
| Hairline | `#D8D2C4` | Row separators; the **connector/edge stroke hue** (as a translucent tint — see below) |

**Amber (`#C8742B`) reserved exclusively for (this phase, consistent with the marker rule):**
1. The **selected relationship's connector** on the map (stroke + arrowhead) — mirrors the selected-marker ring.
2. The **focused / ego-highlighted graph node** ring (D-12, opening the graph from a profile) and a **selected graph node/edge**.
3. The focus ring on interactive DOM controls in the add-relationship flow (inherited).

Amber is **never** used for: a default (unselected) connector or edge, the "+ Add relationship" button (it is a neutral paper button — creation-of-a-relationship is authoring inside a profile, not the shell's one amber `+ Person` act), direction arrowheads on unselected links, or group/type glyphs.

### Canvas content colors (map connectors — drawn on slate, must read light-on-dark)

Because connectors sit on the **dark** slate canvas beneath bright avatar rings, they use a **warm translucent hairline tint**, not solid ink (ink would vanish on slate):

| Connector state | Stroke | Width @1.0 zoom | Arrowhead (directed) |
|-----------------|--------|-----------------|----------------------|
| Default | `rgba(216,210,196,0.55)` (hairline `#D8D2C4` @ 55%) | 1.75px | filled triangle, same color, ~10px |
| Hover | `rgba(216,210,196,0.85)` | 2px | same, brighter |
| Selected | **amber `#C8742B`** (solid) | 2.5px | filled amber triangle, ~11px |
| Label pill (toggle ON) | paper-shade `#E7E2D6` bg, ink `#26211A` text, `radius-sm`, hairline border | Inter 13px | drawn at line midpoint |

### Graph content colors (Cytoscape — slate background, paper nodes)

| Element | Fill / stroke | Notes |
|---------|---------------|-------|
| Graph background | slate `#1B2230` | Matches the map canvas (continuity) |
| Person node | circular avatar (or paper-shade `#E7E2D6` + initials fallback, ink), **2px paper `#F4F1EA` ring** | Reuses the marker signature; 48px @1.0 |
| Group node | paper-shade `#E7E2D6` rounded-square + `UsersRound` glyph, ink `#26211A` | Reuses the profile TypeGlyph (U2); square vs round distinguishes group from person at a glance |
| Node label | Inter 13px, paper `#F4F1EA` (light-on-dark), below node | Entity name; XSS-safe Cytoscape text |
| Edge (default) | `rgba(216,210,196,0.55)`, 1.75px; arrowhead when `directed` | Same tint as map connectors |
| Edge label | Inter 13px ink-muted `#6B6358` in a paper-shade pill | Relationship `label`; **on by default** in graph (toggle-able, see R5-graph) — the graph is the "explain the connections" view |
| Selected/ego node | **amber `#C8742B`** 3px ring + `0 0 0 4px rgba(200,116,43,.30)` halo | Mirrors selected-marker ring exactly |
| Selected edge | **amber `#C8742B`**, 2.5px | Consistent with connector selection |

Contrast: paper text on slate ≈ 11:1; paper-shade node fill on slate is a light-on-dark surface (node content uses ink on the paper-shade fill ≈ 11:1). Amber ring on slate ≈ AA for a non-text UI indicator. Translucent hairline connector on slate is a decorative stroke, reinforced by the always-solid marker rings it joins.

## Per-Surface Component Specs & States

### R1 — Relationships section (in `ProfileSidebar`, Person + Group)
- **Placement:** a new section built like the existing `groupPlacementsByMap` "Appears on" block — an uppercase Label eyebrow "Relationships", then a list, then the "+ Add relationship" button. **Person & Group profiles only; Locations do NOT get this section** (D-03/D-07 — not valid endpoints).
- **Data:** reactively query `RelationshipLink` records where *this* entity is an endpoint (`fromType/fromId` OR `toType/toId`) — single canonical record, auto-appears on both endpoints (D-04). Planner owns the Dexie reverse index.
- **Row treatment:** each row is `[direction glyph] [label] · [other endpoint name]`.
  - Direction glyph: `→` (Lucide `ArrowRight`) when `directed` and this entity is the `from` end; `←` when this entity is the `to` end of a directed link; `↔` (Lucide `ArrowLeftRight`) when `directed:false` (symmetric). Glyph is ink, never amber.
  - Label (e.g. "mentor of") in Body/16; other-endpoint name is a click target that opens that endpoint's profile via existing `onOpenEntity`.
  - The whole row opens the **relationship record** profile (R3) on click; the endpoint name opens the **endpoint** — two distinct affordances, so the endpoint name is a nested button with its own hit area.
- **States:**
  - **Empty:** muted single line — **"No relationships yet."** with the "+ Add relationship" button beneath (mirrors "Not placed on any map yet.").
  - **Deleted endpoint (orphan guard):** if the other endpoint was deleted, show a muted **"(deleted {person|group})"** row instead of crashing — mirrors the "(deleted map)" pattern (T-03-10). Deleting an entity should cascade-drop its links (repository, D-05 area).
  - **Loading:** the reactive query yields nothing briefly — render the eyebrow + a quiet placeholder, never a spinner-only dead end.

### R2 — Add-relationship flow ("+ Add relationship")
- Trigger: neutral **paper** button (NOT amber) with a leading `Plus` glyph, full-width at the foot of the R1 section.
- Flow (three quick decisions, reuse existing entity-picker patterns like `PersonPicker`):
  1. **Pick the other entity** — a searchable picker over valid endpoint types for the current entity: from a Person → People or Groups; from a Group → People or Groups (person↔person, person↔group, group↔group; D-01). Locations never appear.
  2. **Set direction** — a two-option control: **"Directed"** (renders `A → B`, arrowhead) vs **"Mutual"** (renders `A ↔ B`, plain line). Default **Mutual** (symmetric is the safer, most common default). When Directed, show a tiny "{This} → {Other}" preview so the author knows which way the arrow points; offer a swap affordance.
  3. **Fill label / date / notes** — the relationship's own data (REL-02): `label` (e.g. "mentor of"), `date` (date input, ISO), `notes` (multiline). All optional; label strongly encouraged.
- **Write:** one canonical `RelationshipLink` with `fromType/fromId`, `toType/toId`, `directed` (D-01/D-04). Appears immediately on both endpoints (reactive) and, if both are people placed on the active map, as a connector (R4).
- **States:** saving-offline reuses the inherited **"Saved locally · will sync to Drive when reconnected."** hint. If the picker returns no candidates (e.g. a lone group with no other entities yet), show **"Add another person or group first, then you can relate them."**

### R3 — Relationship record profile (reuse, D-06)
- Opening a relationship (from an R1 row or the relationship-links browse list) opens the **existing full `ProfileSidebar`** entity profile — it already renders `label` / `date` / `notes` / gallery / custom fields for `relationship-links` (see `ProfileSidebar.tsx` l.371–387). No separate slim editor.
- The header shows the relationship as a first-class entity (`ArrowLeftRight` type glyph, Fraunces name). Planner may add a read-only **"Between"** row naming the two endpoints (each a link to its profile) — recommended for orientation, using the same nested-button endpoint pattern as R1.
- **Delete** uses the existing list-context destructive action (brick "Delete relationship-link"); confirmation copy in the Copywriting Contract.

### R4 — Map connectors layer (canvas, non-interactive)
- **Layer model:** a **dedicated Konva `Layer` with `listening={false}`, inserted between L0 (background) and L1 (content)** so connectors always paint **beneath** marker content (D-08) and never intercept marker drags/clicks (D-10, viewer-only). This adds a physical layer to the existing L0/L1/L2 stack; it is NOT a user-facing logical layer.
- **Geometry:** each connector is a Konva `Line` (+ optional arrowhead) drawn in **IMAGE space, composed through `MapDoc.backgroundTransform`** — identical to markers (Phase-3 anchoring), so connectors **follow markers live on drag** and stay anchored on background re-fit (D-08). Endpoints resolve: relationship `personId` → that person's marker(s) on the **active** map.
- **Render rule (D-07):** a connector draws **only when BOTH endpoints are people who each have a person-marker on the active map.** Person↔group and group↔group links are **graph-only** (groups have no marker) — they never render here.
- **Multi-placement (Claude's discretion, D-16 precedent):** if a person has several markers on the same map, **draw one connector to that person's primary/first placement** (keep it simple and legible — one line per relationship, not a fan). Planner may revisit; default is primary-only.
- **Arrowhead:** rendered at the `to` end only when `directed` (D-01).
- **Performance:** if the connectors layer adds render load at high marker counts, apply Konva shape caching / viewport culling (01-RESEARCH Pattern 5) — the same treatment markers already use.
- **States:** no connectors = simply nothing drawn (no empty state on the canvas; the absence is the state). Dragging a marker moves its connectors live. Selecting a connector's underlying relationship (via profile/graph) highlights it amber.

### R5 — Connector-label toggle
- **On the map:** connector labels are **OFF by default** with a **show/hide toggle in the existing map `LayersPanel`**, placed beside / mirroring the Phase-3 D-20 **"Names"** (marker-name) toggle. Label text: **"Relationship labels"**. When ON, each connector shows its `label` in a paper-shade pill at the line midpoint (Inter 13px). Rationale: keep the canvas clean and cheap at scale (D-09).
- **In the graph:** edge labels are **ON by default** (the graph exists to *explain* connections), with the same toggle available in the graph toolbar for dense graphs. This asymmetry is intentional: the map optimizes for spatial clarity, the graph for relational legibility.

### R6 — Graph view (Cytoscape, viewer-only)
- **Entry:** a new **"Graph"** item in `ViewSwitcher` (D-11), Lucide `Share2` (or `Workflow`) glyph, ink text, `aria-current="page"` + 3px ink-muted left bar when active (same treatment as every other view; amber is NOT used for the active nav item — inherited rule).
- **Surface:** full-bleed Cytoscape canvas on the **slate `#1B2230`** background (continuity with the map). A slim top toolbar (paper) hosts the "Relationship labels" toggle and a note that the graph is **viewer-only** (no add/edit affordances — locked by PROJECT.md).
- **Nodes:** people = round avatar (initials fallback), groups = paper-shade square + `UsersRound` glyph (D-11). **Relationship-links are EDGES here, not nodes**, even though they are entity records.
- **Edges:** one per `RelationshipLink`; labeled by default; arrowhead when `directed` (D-01/D-11).
- **Layout:** **force-directed `cose`** by default (D-13). **Persist/pre-cache node positions** so large graphs don't re-layout from scratch on every open (roadmap light-research flag; planner owns the cache mechanism — a positions map keyed by entity id, invalidated when the node set changes).
- **Interaction (D-12):**
  - **Click a node → open its `ProfileSidebar`** (reuse the existing panel; nodes are people/groups, both first-class).
  - **Opening the graph from an entity's profile centers + amber-highlights that node** (ego emphasis) — implemented as focus/highlight state on the existing graph, NOT a separate view mode. Pan/zoom to fit the ego node; neighbors keep default styling.
  - Pan/zoom only otherwise; **no drag-to-connect, no node dragging that mutates data** (viewer-only).
- **States:**
  - **Empty (no relationships in the DB):** centered on slate — a `Share2` glyph (amber, 32px), Display 28px heading **"No connections yet."**, Body sub-line **"Add relationships from a person's or group's profile, then come back to see how everyone connects."** No CTA button here (authoring lives in profiles, not the graph — D-03).
  - **Isolated nodes:** entities with zero relationships still render as unconnected nodes (so the graph is a faithful census), floated at the periphery by `cose`.
  - **Loading (layout computing on a large graph):** a quiet "Laying out graph…" shimmer over the slate; never blocks; falls back to cached positions instantly when available.
  - **Deleted endpoint mid-session:** the reactive rebuild drops the edge/node cleanly (no dangling edge).

### R7 — Graph node → AT bridge (accessibility)
- The Cytoscape canvas is **opaque to screen readers**, exactly like the Konva map (`01-UI-SPEC.md` canvas→AT bridge). Selection MUST reach keyboard/AT users the same way markers do:
  - Clicking (or activating) a node **opens the `ProfileSidebar` and moves focus into it**, and a visually-hidden `aria-live="polite"` region announces **"Selected {Name}"** (the sidebar already implements this — reuse it).
  - A **DOM fallback list of graph entities** is satisfied by the existing People / Groups / Relationship-links browse views — every node is reachable there without the canvas. (Full in-canvas keyboard traversal of the graph is **deferred**, consistent with the Phase-1/3 marker decision; noted in Accessibility.)

## Assumptions

| # | Assumption | Rationale | Reversal cost |
|---|------------|-----------|---------------|
| B1 | **Default connector/edge stroke is a translucent warm hairline** (`rgba(216,210,196,0.55)`), not solid ink. | Solid ink `#6B6358` disappears on the dark slate canvas; a warm translucent line reads as quiet-but-present beneath bright marker rings. Keeps amber free for selection. | Low — a single token. |

| B7 | **Connectors render on a dedicated `listening={false}` Konva layer inserted between L0 and L1.** | D-08 says "beneath the marker content" + "non-interactive"; a separate non-listening layer is the cleanest way to guarantee both without touching marker hit-testing. | Low — layer insertion only. |
| B8 | **Group node = paper-shade square + glyph; Person node = round avatar.** Shape distinguishes type at a glance. | Reuses the existing profile TypeGlyph treatment (U2); round-vs-square is a pre-attentive type cue without spending a color. | Low. |
| B9 | **Graph inherits the slate canvas + paper nodes** (not a light background). | Explicit Phase-1 forward note (`01-UI-SPEC.md` l.308) for visual continuity with the map. | Low. |
| B10 | **In-canvas keyboard traversal of the graph is deferred**; the AT path is node-click → sidebar + the DOM browse lists. | Matches the Phase-1/3 marker decision; full canvas a11y is a known deferred item, not a Phase-4 regression. | Medium — a future a11y phase. |
