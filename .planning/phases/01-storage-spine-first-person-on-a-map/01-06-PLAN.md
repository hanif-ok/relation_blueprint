## Interface Context for Executors

`DriveProvider` MUST implement the exact `StorageProvider` interface from Plan 02 so the Plan 05 `SyncEngine` works against it unchanged. Drive REST specifics (RESEARCH ## Pattern 2 ## Code Examples, all verified):
- `writeFile` (new file) -> `POST .../upload/drive/v3/files?uploadType=multipart` (metadata + content in one request).
- `overwriteFile` (manifest commit ONLY) -> `PATCH .../upload/drive/v3/files/<id>?uploadType=media`.
- `ensureFolder` -> `GET files?q=name='Relation Blueprint' and mimeType='...folder' and trashed=false` then `POST files` if absent (VISIBLE folder).
- `readFile` -> `GET .../drive/v3/files/<id>?alt=media`.
- Every call attaches `Authorization: Bearer <in-memory token>`; a `401` throws `TokenExpiredError` which pauses sync and raises the Reconnect banner.

Auth (RESEARCH ## Pattern 1): `google.accounts.oauth2.initTokenClient({ client_id: import.meta.env.VITE_GOOGLE_CLIENT_ID, scope: 'https://www.googleapis.com/auth/drive.file', callback, error_callback })`; `requestAccessToken()` from a click; `google.accounts.oauth2.revoke(token)` on disconnect.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app -> Google Drive (REST over CORS) | The user's own Drive reached directly from the SPA; the only external service |
| GIS token client -> in-memory token | The access token is the most sensitive runtime secret; its handling is the core security control |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Information Disclosure / Elevation | OAuth access token | mitigate | Token in memory ONLY, ~1h lifetime, never persisted to IndexedDB/localStorage; `revoke()` on disconnect (RESEARCH ## Security Domain V3) — asserted by `tests/storage/auth.test.ts` |
| T-06-02 | Elevation of Privilege | OAuth scope | mitigate | `drive.file` scope ONLY — least privilege; app touches only files it created; consent wording human-verified to not list "all your Drive files" (SC#1, RESEARCH Pitfall 1) |
| T-06-03 | Denial of Service / data loss | Token expiry mid-write | mitigate | Local-first write queue; on 401 pause sync + non-destructive Reconnect banner; never auto-pop consent mid-write (RESEARCH Pitfall 4) |
| T-06-04 | Information Disclosure (XSS reads token) | user-rendered text | mitigate | No `dangerouslySetInnerHTML` (enforced in Plan 03); short token blast radius (~1h, revocable) |
| T-06-SC | Tampering | (Drive REST / GIS — no new npm installs in this plan) | accept | No package installs here; the GIS script tag was added in Plan 01 from the verified Google CDN; legitimacy gate satisfied in Plan 01 |
</threat_model>
