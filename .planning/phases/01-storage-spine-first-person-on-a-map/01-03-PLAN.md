## Phase Goal

**As a** single curator of a private people-and-places dataset, **I want to** connect my own Google Drive, create a person, place them on an image-map, open their profile, and export then restore my whole database, **so that** I own my entire database in my own cloud with no server and can trust the storage spine before I put real data in it.

## Acceptance Criteria (this plan — the Walking Skeleton proof)
- [ ] Upload an image -> map renders on a dark Konva Stage (MAP-01).
- [ ] Create a person with name/photo/phone/description/tags/notes (DATA-02) and place them as a round avatar marker (MAP-04).
- [ ] Click the marker -> profile sidebar shows all data (PROF-01); Edit and Delete work (DATA-04).
- [ ] Dragging the marker persists position; reload restores it (Dexie is source of truth).

<objective>
Deliver the headline Walking Skeleton slice end-to-end against the local data backbone: upload an image to make a map, create a Person with the DATA-02 fields, render that Person as the signature round photo-avatar marker on a dark Konva Stage, drag it (position persists), click it to open the right-docked profile sidebar, and edit/delete the person. This proves one real UI interaction wired to one real Dexie read/write — the spine the rest of the phase widens.

</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user input -> DOM render | Person name/notes/tags are user-controlled text rendered in the profile and marker |
| uploaded image -> Canvas decode | An untrusted image file is decoded client-side for the map background |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure (XSS) | Profile sidebar / marker rendering of user text | mitigate | All user text rendered as React children; NO `dangerouslySetInnerHTML` anywhere (an XSS could exfiltrate the in-memory Drive token) — RESEARCH ## Security Domain |
| T-03-02 | Denial of Service | Oversized/malformed uploaded map image | mitigate | 25 MB cap + JPG/PNG/WebP allowlist + decode-failure error copy; never blocks the shell (UI-SPEC S2) |
| T-03-03 | Denial of Service / data loss | Accidental person deletion | mitigate | Destructive ConfirmDialog with explicit "can't be undone unless you restore a backup" copy; restore path is tested in Plan 07 |
</threat_model>
