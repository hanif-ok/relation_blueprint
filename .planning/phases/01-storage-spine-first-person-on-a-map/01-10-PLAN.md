<objective>
Fix GAP 2 (MINOR — lower-priority enhancement, clearly secondary to 01-09): on refresh, Drive shows disconnected and the user must click Reconnect on every reload. Root cause (confirmed in .planning/debug/drive-reconnect-on-refresh.md): the GIS access token is in-memory only and intentionally never persisted (token-never-persisted invariant), so every reload starts with token=null. The SILENT re-acquire primitive already exists in `src/storage/drive/auth.ts` (`connect({ silent: true })` → `requestAccessToken({ prompt: '' })`) but is never invoked at startup — `runConnect()` calls `driveConnect()` non-silent and only on user gestures, and `App.tsx` has no mount-time restore effect.

This plan adds exactly ONE on-load silent re-acquire that re-establishes the Drive session across reloads without a popup, and without persisting the token. On failure (no active grant) it falls back to not-connected quietly — no scary error pill for a benign no-session case.

Purpose: Remove the per-refresh Reconnect papercut while preserving the hard security invariant (token-never-persisted).
Output: A `restore()` action on `useConnectDrive` (silent connect; quiet failure), a single mount effect in App.tsx that calls it once when configured, and a test asserting the silent-on-load path works AND persists nothing.

NOTE: This is the MINOR gap. It is independent of 01-09 (no shared files) and may run in the same wave. If time/scope is constrained, 01-09 (MAJOR) takes priority — this enhancement must not regress the green gate or the auth security tests.
</objective>
