# Phase 1 — UI Design Contract

> Visual and interaction contract for the Walking Skeleton. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> This contract also **seeds the foundational visual language** for all six phases. Tokens here are forward-looking; Phase-1 surfaces are the only ones specified in detail.

---

## Design Direction (point of view)

**"The lit field map."** Relation Blueprint is a private dossier / case-board tool, not an admin dashboard. A single curator answers "who is where, what are they like, how do they connect" against data they fully own with no server. The interface is built around that:

- **The map is the hero and stays dark.** A deep slate canvas keeps uploaded floor-plans, site photos, and round avatar markers legible, and makes the curator's content — not our chrome — the brightest thing on screen. The canvas is a Konva `Stage`, not DOM.
- **The chrome is warm "paper."** The dossier side (top bar, profile sidebar, forms, menus) uses warm off-white panels — the human, hand-curated half of the app. Paper over slate gives the product a tactile, case-file identity.
- **One accent: the amber pin.** A single warm amber is reserved exclusively for *placement and selection* — the act of putting a person somewhere and the marker currently in focus. Amber never decorates generic buttons. This makes "who is where" feel like a deliberate act, not a form submission.
- **Signature element:** the round photo-avatar marker with its amber selection ring and short pin-stem — the literal embodiment of the core value. Its full visual spec is defined in canvas terms below.

This deliberately avoids the three templated AI looks (cream+serif+terracotta; near-black+acid-green; broadsheet hairlines). Slate canvas + warm-paper chrome + a single reserved amber is a choice made for *this* brief.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (deliberate — no shadcn/Material; see Assumptions A1) |
| Preset | not applicable |
| Component library | none mandated. Headless **Radix UI primitives** permitted *only* for accessible Dialog, DropdownMenu, and focus-trap behavior — they ship unstyled, so they do not impose a templated look. All visuals come from the tokens below. (Assumption A2) |
| Icon library | **Lucide** (`lucide-react`) — MIT, tree-shakeable, single coherent line-icon set. Stroke 1.75px to match the paper/line feel. (Assumption A3) |
| Font | Display/entity-name: **Fraunces** (variable, optical sizing). Body/UI/data: **Inter**. Mono (IDs, file sizes, sync timestamps): **JetBrains Mono**. All OFL/free, self-hosted via `@fontsource` for offline-first. (Assumption A4) |

**Styling approach:** CSS custom properties (design tokens) on `:root` + plain CSS Modules or a single `tokens.css`. No CSS-in-JS dependency. Tokens are the single source of truth; Konva marker styling reads the same hex values from a shared TS `tokens.ts` export so canvas and DOM never drift. (Assumption A5)

## Spacing Scale

8-point scale (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, pill inner padding |
| sm | 8px | Compact stacking, field-label to input |
| md | 16px | Default element spacing, form field gaps, sidebar padding |
| lg | 24px | Section padding inside sidebar/form, top-bar horizontal padding |
| xl | 32px | Group separation, gallery grid gaps at large size |
| 2xl | 48px | Empty-state vertical rhythm, major panel breaks |
| 3xl | 64px | Empty-state top offset, page-level breathing room |

**Exceptions:** Touch/click targets for icon-only controls (overflow menu, status pill, gallery thumbnails) are a minimum **44px** hit area even when the glyph is smaller — accessibility requirement, not a spacing-scale value. Top bar height is fixed at **56px**.

## Typography

Four declared roles. Heading/display line-height 1.2, body 1.5.

| Role | Family | Size | Weight | Line Height | Usage |
|------|--------|------|--------|-------------|-------|
| Display | Fraunces | 28px | 560 (semibold) | 1.2 | Entity name in profile sidebar header; empty-state heading |
| Heading | Inter | 20px | 600 (semibold) | 1.2 | Form title, section titles, dialog titles |
| Body | Inter | 16px | 400 (regular) | 1.5 | Field values, descriptions, notes, body copy |
| Label | Inter | 13px | 600 (semibold) | 1.35 | Field labels, status-pill text, menu items, eyebrows (uppercase, +0.04em tracking) |

**Weight discipline:** exactly two weights per family in use — Inter 400 + 600; Fraunces 560 (single display weight). Mono (JetBrains Mono 400, 13px) is utility-only for IDs / file sizes / "synced 2m ago" timestamps and is not a primary text role.

## Color

Dark map canvas + warm paper chrome + one reserved amber accent. Phase 1 ships **light theme paper chrome over a permanently-dark canvas** (the canvas is dark regardless of theme — it is content, not chrome).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F4F1EA` (warm paper) | All DOM chrome backgrounds: top bar, sidebar, forms, menus |
| Canvas surface | `#1B2230` (deep slate) | The Konva Stage background behind uploaded maps. Content layer, not counted in the 60/30/10 chrome split — it is the hero surface. |
| Secondary (30%) | `#E7E2D6` (paper-shade) | Cards, gallery tiles, inset field wells, sidebar vs top-bar separation, hover fills |
| Accent (10%) | `#C8742B` (amber) | See reserved list below |
| Destructive | `#B23A2E` (brick red) | Delete person action + its confirmation only |
| Ink (text) | `#26211A` primary / `#6B6358` muted | Body and label text on paper |

**Accent (amber `#C8742B`) reserved exclusively for:**
1. The primary `+ Person` action (the one creative act in the shell).
2. The **selected marker's** ring + pin-stem on the canvas.
3. The marker **placement** affordance (drag-to-place / "drop here" target).
4. The `Synced` dot in the Drive status pill when a successful sync just completed (brief confirmation), and the focus ring on interactive controls.

Amber is **never** used for: secondary buttons, links in body text, generic hovers, the Edit button, or decorative fills.

**Semantic sync/connection states** (status pill — these are functional state colors, not the accent):

| State | Dot color | Pill text | Label |
|-------|-----------|-----------|-------|
| Synced | `#3E8E5A` (green) | ink-muted | `Drive · Synced` |
| Syncing | `#C8742B` (amber, pulsing) | ink-muted | `Drive · Syncing…` |
| Offline | `#6B6358` (slate-grey, hollow dot) | ink-muted | `Offline · changes saved locally` |
| Reconnect needed | `#C2922A` (caution ochre) | ink primary | `Drive · Reconnect` (actionable) |
| Error | `#B23A2E` (brick) | ink primary | `Sync failed · Retry` |
| Not connected | `#6B6358` (hollow dot) | ink primary | `Connect Drive` |

Contrast: all text/background pairs meet WCAG AA (paper ink `#26211A` on `#F4F1EA` ≈ 11:1; muted `#6B6358` on paper ≈ 4.6:1; white on amber ≈ 4.6:1; white on brick ≈ 5.4:1).

## Round Photo-Avatar Marker (canvas spec — the signature element)

Drawn on the Konva `Stage`, NOT in CSS. Specified in canvas coordinates. A marker = a `Group` (draggable) containing a circular-clipped avatar image + a ring + a short pin-stem, with a fallback when no photo exists.

| Property | Value | Notes |
|----------|-------|-------|
| Avatar diameter (R\*2) | **48px** at 1.0 zoom | `clipFunc` circular crop of the thumbnail (`ctx.arc(R,R,R,…)`), R = 24 |
| Ring (default) | 2px stroke `#F4F1EA` (paper) | Keeps the avatar readable against the dark canvas; subtle outer `0 1px 3px rgba(0,0,0,.45)` shadow |
| Ring (hover) | 2px `#F4F1EA` + outer glow `0 0 0 3px rgba(200,116,43,.25)` | Cursor → pointer; signals "clickable" |
| Ring (selected) | **3px amber `#C8742B`** + outer `0 0 0 4px rgba(200,116,43,.30)` | The one place amber lives on canvas; mirrors DOM focus |
| Pin-stem | 8px tall, 3px wide, color = current ring color, below the circle | Tip touches the geographic point; the circle floats above it. Makes "placed *here*" literal |
| Fallback (no photo) | Filled circle `#E7E2D6` (paper-shade) + person's initials in Inter 600, ink `#26211A`, centered | Never a broken-image box. Up to 2 initials |
| Dragging | Opacity 0.9, lift shadow `0 6px 14px rgba(0,0,0,.5)`, ring stays amber if selected | Position commits to repo on `onDragEnd` |
| Placement target | While placing a new person: a pulsing amber `0 0 0 2px` dashed ring ghost follows the cursor | Click commits position |
| Hit area | The full 48px circle + stem bounding box | ≥ 44px target satisfied |

**Selection communication (non-visual):** the canvas is keyboard-and-AT-opaque, so marker selection is mirrored into DOM: selecting a marker (click) **opens the profile sidebar and moves focus to it**, and the sidebar header announces the person's name (`aria-live="polite"`). A visually-hidden status region announces "Selected {Name}". This is how canvas selection reaches keyboard and screen-reader users in Phase 1. (Full canvas keyboard nav — tabbing between markers — is deferred; noted in Accessibility.)

## Per-Surface Component Specs & States

### S1 — Top bar / app shell
- Layout: 56px tall, paper bg, `elevation-1` bottom edge. Left: diamond mark `◆` + wordmark (Fraunces 20px). Right cluster (gap md): Drive status pill, `+ Person` (amber primary button), overflow `⋯` (icon button, 44px hit area).
- `+ Person` is disabled-with-reason only if no map exists yet (tooltip: "Upload a map first"); otherwise always enabled (works offline — creation is local).
- States: see status pill (S9) and reconnect banner (S8).

### S2 — Map view
- **Default (map present):** full-bleed dark Konva Stage; background image layer + marker layer. Pan/zoom is basic (drag-pan, wheel-zoom) — full editor is Phase 3, keep minimal.
- **Empty state (no map):** centered on the slate canvas — a dashed paper-bordered drop zone, `radius-md`, with: map-pin Lucide glyph (amber, 32px), Display 28px heading, body sub-line, and an "Upload map image" button (secondary paper button).
  - Heading: **"Start with a place."**
  - Body: **"Upload a floor plan, site photo, or any image to use as your map. Then you can place people on it."**
  - Button: **"Upload map image"**
- **Loading (image decoding):** drop zone shows a quiet shimmer + "Preparing map…"; never blocks the rest of the shell.
- **Error (bad/oversized image):** inline under the drop zone, brick text: **"That image couldn't be loaded. Try a JPG, PNG, or WebP under 25 MB."**
- **Offline:** fully functional — map renders from IndexedDB; no network gating.

### S3 — Person create / edit form
- Out-of-box fields ONLY (DATA-02): **Name** (required), **Photo** (single avatar upload + preview), **Phone**, **Description** (short text), **Tags** (chip input), **Notes** (multiline). No custom fields (Phase 2).
- Layout: docked-right panel on wide viewports, full-screen modal on narrow. `elevation-2`, paper bg, `radius-md`. Title row + scrollable field body + sticky footer actions.
- Field treatment: Label (13px/600) above input; inputs on paper-shade well with hairline border; `radius-sm`; amber focus ring (2px). Tags render as paper-shade `radius-pill` chips with a remove `×`.
- Footer: primary **"Save person"** (amber on create, neutral-ink on edit to keep amber reserved for *creation*; on edit the primary is paper-inverse ink button), secondary **"Cancel"**.
- States:
  - Validation (empty name on save): inline brick message under Name — **"Add a name so you can find this person."** Save stays disabled until name is non-empty.
  - Photo processing: avatar preview shows shimmer while client-side thumbnail generates; form remains submittable (photo optional).
  - Saving offline: footer hint, mono/muted — **"Saved locally · will sync to Drive when reconnected."**

### S4 — Profile sidebar
- Opens on marker click; docked right, `elevation-2`, paper, overlays the canvas; width 360px (wide) / full-screen (narrow).
- Header: round thumbnail (avatar or initials fallback, 48px) + entity name (Fraunces 28px display).
- Body: all DATA-02 fields rendered read-only — Phone, Description, Tags (chips), Notes; a **photo gallery** grid (paper-shade tiles, `radius-md`, gap sm, lazy-loaded) for PROF-02. Empty field rows are omitted, not shown blank.
- Actions: **"Edit"** (neutral paper button) + **"Delete"** (text button, brick ink). Close affordance: `×` top-right + Esc.
- States:
  - Gallery empty: a single muted line — **"No photos yet."** (no button here; photos are added via Edit).
  - Image still loading: tile shimmer.
  - Delete: see destructive confirmation below.

### S5 — Export / Restore (overflow menu)
- **Export backup** → triggers file save (`relation-blueprint-backup-YYYY-MM-DD.json`). While bundling: menu item shows inline spinner + "Preparing backup…". Success toast: **"Backup saved."**
- **Restore backup** → file picker → confirmation dialog (restore is destructive: it replaces the local database). Dialog copy under destructive confirmation below. On success: toast **"Backup restored."** On invalid/corrupt file (zod fail): dialog error — **"This file isn't a Relation Blueprint backup, or it's damaged. Your current data is untouched."**

### S6 — PWA install prompt
- Dismissible toast (bottom) when installable, plus a persistent **"Install app"** overflow item.
- Copy: heading **"Install Relation Blueprint"**, body **"Add it to your device to open it offline, like a native app."**, actions **"Install"** / **"Not now"**.
- After a meaningful action, request `navigator.storage.persist()`; if denied, a one-time muted note in the overflow/about area: **"Your device may clear offline data when storage is low. Export backups regularly."**

### S7 — Update-available prompt
- Toast (bottom), `elevation-2`: **"A new version is ready."** body **"Reload to update."** actions **"Reload"** / **"Later"**.
- "Reload" only activates the waiting service worker when no write is in flight (guarded); if a sync is mid-flight, the toast shows **"Finishing sync…"** then proceeds. Never silently swaps.

### S8 — Reconnect-to-Drive banner (non-destructive)
- Inline banner directly under the top bar, caution-ochre left edge, paper bg. Appears on token expiry / 401. Non-blocking — the app stays fully usable offline.
- Copy: **"Drive needs to reconnect to sync your changes. Your work is saved locally."** action **"Reconnect"** (re-runs the GIS token request on click — required user gesture).
- Dismissible; reappears on next failed sync attempt. Never destroys or blocks local state.

### S9 — Drive status pill
- Compact pill in top bar; dot + label per the semantic states table above. Clickable in actionable states (Connect / Reconnect / Retry) — opens the relevant flow. `Synced`/`Syncing`/`Offline` are informational (still focusable, with a tooltip showing last-sync timestamp in mono: "synced 2m ago").

## Accessibility & Interaction

**Focus & keyboard (DOM chrome):**
- Visible focus ring on every interactive control: 2px amber (`#C8742B`) outline + 2px offset. Never remove outlines without replacement.
- Tab order: top bar (wordmark skipped) → status pill → `+ Person` → overflow. Reconnect banner, when present, is reachable right after the top bar.
- **Dialogs & forms (S3, delete, restore):** focus trapped while open, focus returns to the trigger on close, **Esc** closes (Cancel semantics). First focus lands on the first field (form) or the safe/Cancel button (destructive dialogs).
- **Overflow menu (S5/S6):** arrow-key navigation, Esc closes, Enter/Space activates — use Radix DropdownMenu for correct roving focus.
- **Profile sidebar (S4):** opening moves focus into the panel; Esc / `×` closes and returns focus to a stable anchor (the `+ Person` button, since the originating marker isn't a DOM node).

**Canvas selection (Konva) → AT bridge:**
- The canvas itself is not keyboard-traversable in Phase 1 (deferred — Phase 3 introduces many markers and proper canvas keyboard nav).
- Marker selection is surfaced to AT by: (a) opening the profile sidebar with focus moved into it, (b) an `aria-live="polite"` announcement "Selected {Name}", (c) the selected marker's amber ring as the visual mirror.
- A persistent, accessible **people list fallback is NOT required this phase** (browse is Phase 2), but every person created remains reachable: clicking their marker is the Phase-1 path, and the profile is fully keyboard-operable once open.

**States coverage (every surface declares):** loading (shimmer, never blocking), empty (directive copy), error (problem + fix in interface voice), offline (reassurance, full function). No spinner-only dead-ends.

**Motion:** respect `prefers-reduced-motion` — the syncing-dot pulse, placement-ghost pulse, and shimmer reduce to static states. Marker drag has no inertia. Animation is restrained (the signature is the marker, not motion).

**Targets:** all icon-only controls and marker hit areas ≥ 44px.

## Forward-Looking Notes (seed for later phases — do NOT build now)

- **Theme:** tokens are structured so a future dark *chrome* theme can swap paper→slate without touching the canvas (canvas is already dark). Out of scope now.
- **Marker variety (Phase 3):** portal/location-link markers will need a *distinct non-round shape* in a different reserved color — keep amber for selection only so portals can claim their own hue. Reserve this now.
- **Entity-type color coding (Phase 2/4):** People are the only entity type in Phase 1. When Locations/Groups/Relationship-links arrive, give each a quiet ink-tint, never another saturated accent — amber stays the single attention color.
- **Tag color (Phase 2):** tags are neutral chips now; if tag-coloring is added later it must not collide with amber.
- **Graph view (Phase 4):** Cytoscape graph should inherit the same slate canvas + paper node treatment for visual continuity.
