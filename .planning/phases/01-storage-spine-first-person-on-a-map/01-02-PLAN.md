## Interface Context for Executors

The `StorageProvider` interface (created here) is the single seam every storage backend implements. Lock these method signatures — Plan 05 (sync engine) and Plan 06 (Drive adapter) depend on them:
- `ensureFolder(name: string, parentId?: string): Promise<string>` — returns folder id, idempotent
- `list(folderId: string): Promise<FileEntry[]>` — `FileEntry = { id, name, size, modifiedAt }`
- `readFile(fileId: string): Promise<Blob>`
- `writeFile(name, parentId, body: Blob, contentType): Promise<string>` — creates a NEW immutable file, returns its id
- `overwriteFile(fileId, body: Blob, contentType): Promise<void>` — in-place overwrite (ONLY used for the small manifest commit point)
- `delete(fileId: string): Promise<void>`
- `stat(fileId: string): Promise<FileEntry>`

The `Manifest` type (created here) is the single commit point for atomic writes: `{ version: number, updatedAt: number, shards: Record<EntityType, ShardPointer>, backups: string[] }` where `ShardPointer = { fileId, hash, updatedAt }`.
