## Phase Goal

**As a** single curator of a private people-and-places dataset, **I want to** connect my own Google Drive, create a person, place them on an image-map, open their profile, and export then restore my whole database, **so that** I own my entire database in my own cloud with no server and can trust the storage spine before I put real data in it.

## Acceptance Criteria (this plan)
- [ ] App installs as a PWA and opens/works offline (STOR-06).
- [ ] `navigator.storage.persist()` is requested after a user action and its result surfaced (STOR-06).
- [ ] A new SW prompts to update and never silently swaps mid-write (RESEARCH Pattern 4).

<objective>
Close the spine with the PWA shell: vite-plugin-pwa (Workbox) precaching the app shell for offline open, a controlled `registerType: 'prompt'` update flow that never drops queued writes, the install affordance, and a persistent-storage request made after a meaningful user action.

Purpose: STOR-06 (installable PWA + persistent local storage request) plus the controlled-update requirement (RESEARCH ## Pattern 4 / Pitfall 7) are the last non-retrofittable pieces — a blind `skipWaiting()` could swap assets under an in-flight sync and drop queued writes. The GitHub Pages base-path rule (RESEARCH ## Pattern 4) must be correct or the SW mis-scopes.
Output: the VitePWA config, `src/app/pwa.ts`, the install/update/persistence UI, and the persistence test + install E2E.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| service worker update -> running app | A new SW activating under a running page can swap assets and is the main risk to queued offline writes |
| browser storage eviction -> offline cache | Best-effort storage is evictable; eviction risks unsynced local work |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Denial of Service / data loss | Blind SW update mid-write | mitigate | `registerType:'prompt'` + activate only on user Reload when no write is in flight (RESEARCH ## Pattern 4 / Pitfall 7) |
| T-08-02 | Denial of Service / data loss | Storage eviction of the offline cache | mitigate | `navigator.storage.persist()` requested after a user action + result surfaced + export nudge; cloud sync + export are the backstops (RESEARCH Pitfall 5) |
| T-08-03 | Tampering | Mis-scoped SW serving stale/wrong assets | mitigate | base/start_url/scope all set to the GitHub Pages repo subpath so the SW controls the correct scope (RESEARCH ## Pattern 4) |
| T-08-SC | Tampering | vite-plugin-pwa / workbox-window installs | accept | Both vetted in RESEARCH ## Package Legitimacy Audit (OK, high download counts, canonical repos, no postinstall); installed in Plan 01 |
</threat_model>
