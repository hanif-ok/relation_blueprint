<objective>
Re-arm every vacuous `page.waitForFunction` assertion in the e2e suite, then triage — and STRICTLY
bound — the fallout.

Purpose: `page.waitForFunction(async (…) => …)` does not await the promise its predicate returns.
Playwright truthiness-tests the returned value and a `Promise` is always truthy, so the wait resolves
on its first poll no matter what the predicate would have evaluated to. Every such assertion is a
no-op that always passes. This is PROVEN, not theorised — during quick-260903-d77, with the marquee
coordinate conversion deliberately bypassed, a `page.evaluate` read showed the band had caught only
one of two rects (survivors `["shape-a"]`) while the sibling `waitForFunction(… length === 0)` over
that exact state still went green (D77-DEF-1).

Output: 12 re-armed assertions across 6 specs; the one already-diagnosed test-side bug fixed
(D77-DEF-2); a triage record with a bucket verdict for every test that changed status; a
deferred-items file holding every genuine product defect the re-arming exposes (logged, NOT fixed);
an ESLint guard that fails `npm run lint` if the vacuous form ever returns; and a SUMMARY verdict
stating how much of the suite was passing on nothing.
</objective>

**GUARD-1 recommendation — an ESLint rule, defined inline in `eslint.config.js`. Reasoning:**
1. **AST accuracy is the whole point.** The prior task's census was wrong precisely because it was
   grep-shaped: the predicate sits on the line AFTER `.waitForFunction(` in every multi-line call, so
   a line grep either misses all 12 or (as happened) counts unrelated call sites. A rule reading the
   call expression's first argument cannot make that mistake.
2. **Zero new dependencies.** ESLint 10 flat config accepts a plugin object declared inline in the
   config file, so the rule needs no `eslint-plugin-local-rules` and no npm install — the free/OSS
   and no-new-deps constraints hold.
3. **It runs where the repo already looks.** `npm run lint` is `eslint .`, `e2e/**/*.ts` is already
   in scope (`files: ['**/*.{ts,tsx}']`, and `e2e` is not in `ignores`), so the guard costs nothing
   to adopt and cannot be forgotten.
4. Rejected: a grep in the lint script (fragile, see 1); a documented convention only (this defect
   shipped past two code reviews and a full task — a convention would not have caught it).
Fallback if the inline plugin proves not self-contained: a `scripts/check-e2e-async-waits.mjs` node
script chained into the `lint` script. Documented in Task 3; only used if the inline form fails.
