# Quick Task 260703-f9m: Add a favicon

## Goal

Stop the console `GET /favicon.ico 404` and give the browser tab an icon by adding an SVG favicon
and declaring it in `index.html`. Scope: favicon only — the PWA manifest icon PNGs
(`manifest-icons/*.png`, referenced in `vite.config.ts`) are a separate task.

## Tasks

### Task 1 — Create the SVG favicon
- **files:** `public/favicon.svg` (new)
- **action:** Add a small on-brand SVG (`viewBox 0 0 32 32`) — a relationship-graph glyph on the
  slate canvas color (`#1B2230`): two paper nodes (`#F4F1EA`) + one amber accent node (`#C8742B`)
  joined by hairline (`#D8D2C4`) edges. Colors mirror the UI-SPEC tokens (`src/app/tokens.ts`).
- **verify:** file exists and is valid SVG.
- **done:** `public/favicon.svg` present.

### Task 2 — Declare the favicon in index.html
- **files:** `index.html`
- **action:** Add `<link rel="icon" type="image/svg+xml" href="/favicon.svg" />` to `<head>`.
  Root-absolute `/favicon.svg` is correct: Vite auto-rebases `index.html` URLs against
  `base: '/relation_blueprint/'` in dev and build (confirmed via Vite docs), so it resolves to
  `/relation_blueprint/favicon.svg`. Declaring a `<link rel="icon">` also stops the browser's
  automatic root `/favicon.ico` request.
- **verify:** `<link rel="icon">` present; dev serves `/relation_blueprint/favicon.svg` (200) and
  the root `/favicon.ico` 404 is gone.
- **done:** `index.html` references the favicon.
